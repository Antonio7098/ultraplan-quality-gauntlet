## Part 0 — The shared execution skeleton

Every runtime-backed operation (CLI sprint/study, TUI op, browser op) executes over a **two-tier durable spine**:

1. **Outer operation run** — created once per user command/op by `beginDurableCLICommand` (durable_operations.go:49) or the web/TUI `sharedOperationRunner` → `durableOperationManager.AcceptOperation` (:97): repo `Accept(Target.Kind:"operation", ProductStatus:"prepared", OperationAlias=digest)` → alias conflict → `ResolveOperationAlias` → `AcceptedOperation{Existing:true}` (:106-112) → `Claim(Lease=OwnerLeaseDuration)` → fenced `EventLifecycle/Running` append (failure ⇒ terminal `persistence_lost`, :121-128) → child ctx = `WithCancel(WithParentRun(ctx, RunID))` + ownership value → `go controlOperation` (:136).
2. **Inner runtime runs** — every agent call (`sprint.Service` stage/task/QA StartRun at runtime_metrics.go:120 / qa.go:556; study RunAnalysis/Synthesize) goes through `controlledRuntime.StartRun` (run_control.go:159): a **second** `Accept(ProductStatus:"accepted")` + `Claim` + fence, correlated to the outer run via `Correlation.ProductRunID = ParentRun(ctx)` (:161-164), metadata `run_control_run_id` injected into the agent request (:187). So one CLI flow command produces 1 outer run + N inner runs (one per stage/task/shard attempt).

Shared inner-run mechanics (verified verbatim at frozen SHA):
- Event path: wrapped `req.OnEvent` builds a sanitized draft, content-hash coalesces identical `progress` payloads within `ProgressCoalesceWindow=250ms` (model.go:13) into omission counters (:215-236); **delivery is persistence-gated**: the consumer's configured OnEvent fires only after a successful Append (:237-248); first Append failure sets `persistenceErr` and cancels the run ctx (:196-203).
- Control goroutine per run: 1s tick (`OwnerTickInterval`) polls Snapshot for cancellation requests (ack via fenced `AcknowledgeCancellation` then cancel); heartbeat every 5s renewing the 15s lease (`OwnerLeaseDuration`); `Reconcile` sweep every 10s (run_control.go:252-301; model.go:513-521).
- Terminal: trailing coalesced-omission flush under `eventMu` (:303-315); on persistErr → `TerminalPersistenceLost` proposal on detached 30s Background ctx (:322-332); else `terminalOutcome(result, runErr, ctx)` → `proposeRunTerminalWithRetry`: retries `ErrUnavailable|ErrBusy` every ~100ms until the 30s detached ctx expires (single-winner CAS inside runcontrol; losers get existing snapshot).
- Retry helpers: `appendRunEventWithRetry` 5s deadline, ≤100ms sleeps (:345-356); `waitRunControlRetry` caps sleeps at 100ms (:374-390).

Under the inner runs sits the **agent boundary** (`platform/runtime.Adapter.StartRun`): store prep (0700 dir + active `store.json`) → `toAgentwrapRequest` (health/caps whitelist-mapped, permission-policy validation) → metadata injection (`opencode.database_path`, `runtime_store_owner`, cohort prompt-cache keys sha256-derived) → SDK stack `ObservingRuntime{ValidatingRuntime{PolicyRunner{requestVariantRuntime→*opencode.Runtime}}}` with `PersistencePolicy{PersistUnsafeRawPayloads:false}` → binary invocation `opencode run --format json [--dir W] [--model p/m] [--session S] [--variant v]`, prompt on stdin, DB isolation via `OPENCODE_DB` env → event drain goroutine (200-event ring with drop accounting) + `run.Wait` goroutine.

## Part 2 — Seams between surfaces

**X1. Outer↔inner double fencing** — one user operation yields one outer operation run (Kind "operation") plus N inner runtime runs correlated via ProductRunID; two independent leases/heartbeats must stay alive for a clean terminal; cancellation requested against either ID converges because the inner control goroutine watches its own run and the outer watches the operation run; QA publishing heartbeats the OUTER lease from inside sprint Publish (X8). Reviewers should treat lease-liveness mismatches between tiers as first-class hypotheses.

**X2. Runtime→binary hop** — everything above Adapter.StartRun is heavily tested against fakes; everything below (argv construction, OPENCODE_DB isolation, stdin prompt delivery, run.Wait responsiveness during cancel-grace, checkpoint/VACUUM deletion) lives in agentwrap SDK + untested ultraplan-side functions. The 5s synthesized-cancelled return abandons drain/wait goroutines — teardown outcome unobserved by design (runtime.go:369-377).

**X3. Persistence-gated observation** — UI/display callbacks fire only AFTER durable Append succeeds (run_control.go:246-248); display callback suppressed entirely once persistence fails. Consequence: observers never see uncommitted events, but also stall silently during DB pressure until the run aborts TerminalPersistenceLost.

**X4. Shutdown ordering chain** — main NotifyContext(INT,TERM) → web drainAndWait (cancel server_shutdown bypassing ownership → wait ≤10s → leaseless cleanup-uncertain markers persisted BEFORE in-memory projection → cancelOperations → server.Shutdown → cleanup error wins as exit value) → app.Run deferred pool Close LAST. TUI program is NOT ctx-torn-down; study run-loop relies on the same signal converting to ctx cancel; library consumers of app.Run without NotifyContext would take default SIGINT disposition (single signal site repo-wide, cmd/ultraplan/main.go:19).

**X5. Commit-then-publish** — every domain persists state before git publication; publication failure is reported after commit and never rolls back (X-ordered facts in OB2). Paired invariant: QA pointer publish is last of all writes (map-02 SA-8).

**X6. Session continuity seam** — SDK treats SessionID/SessionAction as opaque pass-through; ALL continuation policy is product-side and split three ways: study fingerprint gating (strict, ContinueFailures ladder), sprint stage sessions (.stage-sessions.json, checksum-ignoring, no-fsync file), execute batch sessions (Resume∧path-unchanged seeding + model-match gate). Restart trigger everywhere is the literal substring "session not found" matched against joined error text.

**X7. Process-group discipline split** — smoke/QA subprocesses get DirectRunner group-kill semantics (SIGTERM→5s→SIGKILL, CleanupComplete reporting); OpenCode agent children live under agentwrap's own management whose kill path is unobserved after the 5s grace; study/sprint runtime-store GC may RemoveAll a store directory whose owner was declared dead by kill(0) only (>30min stale-active demotion protects resumability, aggressive mode explicitly sacrifices retained-not-live stores near disk-critical).

**X8. Cross-package fence handoff** — app mints QAWriterToken from the outer runcontrol fence; sprint checks it fail-closed (absence ⇒ conflict) and the check callback heartbeats the outer run (WithoutCancel, 30s). This is the only coupling between sprint publish loops and run-control leases.

**X9. Three-frontends-one-journal** — CLI runs commands, web handlers (timeline/run detail), and TUI run views all read the same cached SQLiteRepository handle per process root; SSE vocabulary is contract-frozen against shipped JS; durable fallback polling exists for streams past hub eviction (hub memory is authoritative only for ≤30m/≤256-event windows).

## Part 3 — Domain grouping & suggested review order

- **durable-core** (DC1 critical, DC2 high, X1/X3/X4): the arbitration spine every surface trusts; heartbeat/CAS/reconcile timing defects corrupt everything downstream.
- **agent-execution** (AE1 high, X2/X6/X7): the only surface where real subprocesses run; cancellation grace abandonment + zero-tested binary-hop functions concentrate here.

- **publication** (OB2 normal): commit-then-publish invariant is load-bearing across all domains.

## Part 4 — Lifecycle invariants observed (for downstream reviewers)

1. Persist-before-launch (execute task state saved before any runtime start — pinned).
2. Commit-before-delivery (OnEvent fires only after Append — pinned).
3. Dedup-before-capacity (web startConfirmed checks dedup before drain/capacity).
4. Marker-before-projection (cleanup-uncertain persisted before in-memory terminal projection).
5. Single-winner terminal CAS everywhere; losers keep existing snapshot.
6. State-committed-then-publish; publish failure never rolls back state.
7. Pointer-last publish for QA privates; flow-state QA pointer written last.
8. Lease-before-work in sprint (mutation lease precedes prompt build and runtime).

11. Session-store removal predicates protect live owners; aggressive GC sacrifices retained stores only under study disk-critical/idle conditions.
12. Exactly three dedup keying regimes (CLI empty, TUI canonical+fingerprint, web session+token) converge on one OperationAlias uniqueness constraint.
