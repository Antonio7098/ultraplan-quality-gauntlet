## Interface topology in one paragraph

One binary, three frontends over one app core. `cmd/ultraplan/main.go` injects `TUIRunner`/`WebRunner` function types into `app.Run` (`internal/app/app.go:144-177`; inversion at `surfaces.go:18-20`); nothing in `internal/app` imports the frontends. One composition root resolves the workspace identically for all three (`discoverWorkspace`, `app.go:287-298`: global `--workspace[=…]` flag → `ULTRAPLAN_WORKSPACE` → cwd-ancestry walk to an `ultraplan.yml` marker), and one SQLite run-control repository per workspace (`.ultraplan/run-control.db`) backs observation, cancellation, and durable acceptance everywhere. CLI handlers mostly call product services directly; TUI and web both drive the shared `OperationalUseCases` boundary (`dashboardUseCases`) plus `DurableOperationManager` + `repositoryRunUseCases`, with runtime-backed work funnelling through one `sharedOperationRunner` (`operation_runner.go:15-166`). Divergence lives in grammar (five arg-parsing styles in the CLI alone), durability mechanics (CLI accepts with empty digest/no dedup vs web session-token dedup keys vs TUI content-derived digests), capability coverage (web-only sprint create/models/timeline/resources; CLI-only code/storage/diagnostics-export/study-reset; TUI-only parallelism form and fixed diagnostic rationale), and composition flags (web builds use cases `readOnly:true`; TUI leaves write-on-refresh enabled).

## Seam register (interface-specific)

1. **Durable acceptance ×3 mechanisms** — `beginDurableCLICommand` (empty digest, sync, no dedup) / web `startConfirmed` (token-derived dedup key, ErrWebUnavailable ephemeral fallback) / TUI `beginOperation` (canonical+fingerprint digest, gated on `Confirmation != nil`). Same `repository.Accept` underneath; connects to map-02's S2/S9.
2. **Operation-kind vocabulary** — Go enum ↔ browser aliases (contract-tested) ↔ TUI typed constants (compile-time only) ↔ CLI durable Target kinds (inventory-scanned, not value-checked).
3. **Cancellation** — three doors into `RequestCancellation` with differing reason vocabularies and target validation; `study-cancel` SIGINT side channel bypasses the durable record entirely.
4. **Observation** — one repository; three projections (text/envelope NDJSON, {data,meta}+SSE, rendered TUI); replay constants triplicated; omissions/gaps surfaced differently per door.
5. **Workspace resolution** — single `discoverWorkspace` for all doors; `init-workspace`/`defaults`/`skills` bypass it; serve freezes identity at boot.
6. **Confirmation authority** — fingerprint is server-issued (caller-supplied values zeroed, rejected at decode, re-checked at execution); TUI/web honour it; CLI has no fingerprint concept at all.
7. **Redaction layers before human eyes** — config.RedactValue (CLI/TUI display), safeProjectedText (web hub), redactObservableValue (tool payloads upstream), safeOperationCause (error gating): four layers, different marker sets and bounds.
8. **Cleanup uncertainty** — web drain persists markers after 10 s deadline; study/sprint owners reconcile fail-closed at next boot/lock; CLI interrupt paths write equivalent markers (map-02 overlap).

## Neutral inventory facts carried forward

- `validCommandOrigin` docstring vs strict-equality body; `validOrigin`/`validOperationReadOrigin`/`eventIDHeader` defined-but-unused.
- Cookie lacks `Secure`; no server-side session expiry (MaxAge browser-side only; HMAC valid until process restart rotates the secret).
- HTML `_csrf` uses `!=`; API header compare is constant-time; JS retries once on 403 adopting the rotated token.
- No per-session operation cap (global 8/32/32); slow subscribers silently disconnected.
- Sprint-create mutation sits outside the prepare/confirm/token machinery (session+origin+form-CSRF only).
