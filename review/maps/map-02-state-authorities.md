## Part 3 — Seams between surfaces

**X1. One file, two packages** — runcontrol and productstate hold independent pools on `.ultraplan/run-control.db`; identical pragmas except runcontrol's extra `_defensive` and post-open verification (productstate verifies nothing, never pings); arbitration relies on BEGIN IMMEDIATE + shared 5s busy_timeout; storage migrate holds both pools simultaneously (up to 4+4 conns). runcontrol documents multi-process intent (sqlite.go:41-42); productstate carries no such comment.

**X2. File↔DB dual-home activation** — presence of DB file + row switches three families to DB-authoritative with different mirror rules (study: Complete-only; flow: all-stages-terminal; execute: all-tasks-terminal); loaders are DB-first with unconditional row-wins; no reverse export; no CLI inspection of stored rows; conversion only via lockless `storage migrate` which keeps source files.

**X3. Shutdown ordering chain** — NotifyContext(ctx; INT,TERM) main.go:19 → web drainAndWait(10s): cancel ops reason server_shutdown (ownership bypass) → wait done per record → deadline → persistCleanupUncertain (leaseless, 1s per-record timeout) → in-memory projection → cancelOperations → server.Shutdown/Close; cleanup error becomes process exit value; runControl.Close() deferred in app.Run runs after drain; TUI bubbletea program is NOT ctx-torn-down (key-driven quit only); runtime Adapter has its own 5s cancel grace inside StartRun.

**X4. Publish-after-commit seams** — study run-loop: forced save→SyncRunHistory→git publish, returning publication failure only after state committed; sprint stages save flow-state then publish owned path sets; one flock serializes publications (no exclusion on non-linux); QA publishes flow pointer last of all.

**X5. Read/write asymmetry across frontends** — sprint.Status may WRITE flow-state (statusWrites) while study status only reconciles in memory; `study runs summary` rewrites ledger+summary without executing; web/tui never touch state files directly (import boundaries enforced by AST tests; web imports runcontrol only in tests; tui imports sprint solely for result types); all frontend access flows through internal/app use cases.

**X6. Clock pluralism** — runcontrol injectable Clock switches expiry predicates between DB-side julianday('now') (production; one time authority across processes, sqlite.go:1132-1144) and bound parameter (tests only — **no production caller injects a clock**); sprint WithClock feeds attempt-expiry and persist-failure tests; study uses raw time.Now().UTC() everywhere including retry delays and debounce; sprint verification 2h heartbeat expiry and runcontrol 15s lease never consult each other though both gate overlapping operations; LocalFileLogger and metrics use wall clock regardless.

**X7. Lease layering** — sprint stacks three mechanisms (in-process sync.Map → pidfile → verification-attempt heartbeats; QA adds writer-token generations rooted in runcontrol claims); study uses one O_EXCL lock with kill(0); runcontrol uses DB leases with birth tokens; shutdown markers deliberately bypass ALL of them (X3) and consumers re-establish leases before consuming them fail-closed.

**X8. Legacy strata** — flow v1→v2 read-time-only upgrade with `"legacy-unverifiable"` digests (never persisted — pinned by test); schemaVersion-0 terminal execute-state immutable history excluded from resume/reconcile/migration; map-era flow (schemaVersion 0/version 1) detected separately; runcontrol backup/restore is the DB-level analogue. Each stratum changes which writer may touch which file.

**X9. Cross-family coupling via app** — durable_operations hands runcontrol-derived fences to sprint as QAWriterToken (sprint never imports runcontrol); web_usecases dispatches cleanup markers study-vs-sprint by operation shape and reconciles both at startup before listen; storage_commands is the sole writer bridging all three families into productstate.
