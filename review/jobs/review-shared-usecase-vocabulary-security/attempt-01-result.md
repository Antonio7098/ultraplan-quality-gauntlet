# Findings — `shared-usecase-vocabulary` (security/misuse lens)

## F1 · HIGH severity, HIGH confidence — TUI accepts a stale unrelated confirmation durably while executing a different operation, falsifying run-control and permanently alias-squatting the real operation

- **Claim**: `beginOperation` binds durable acceptance to whatever `Confirmation` happens to be pending, not to the request it is asked to run (`internal/tui/app.go:232-255`: digest and `AcceptOperation(ctx, *m.model.Confirmation, …)` use `m.model.Confirmation`, while the executed request is the `req` parameter).
- **Trigger**: The only caller that passes a divergent `req` is the study-cancel ladder (`app.go:139`). `Model.setTab` and route navigation never clear `Confirmation` (`internal/tui/model.go:359-374`; only `ActionBack`/`OperationMsg`/same-route guards do, model.go:234, 265-266). Sequence: prepare any operation X (e.g., execute-start) → switch tabs/routes without `esc` → open a study whose summary has `RunActive` (first nav item carries `ViewRun`, model.go:542-543) → press `c`.
- **Execution path**: `ActionCancel` → `beginOperation({Kind: OperationStudyCancel})` → `AcceptOperation(X's confirmation, sha256(canonical_X‖fp_X))` creates a durable run with `Target.Operation=execute-start`, claims it, emits lifecycle-running → `RunOperation(study-cancel)` executes under that run id → `FinishOperation(complete)` proposes terminal `succeeded`.
- **Observable bad outcomes** (both proven by executed test against `5d54525`, output: `PROOF: durable accept recorded kind="execute-start" … while executed kind="study-cancel"`):
  1. Run-control permanently records that execute-start ran and succeeded when only a SIGINT was sent — violating the truthfulness contract ("Every runtime-backed … operation receives a durable run", user-guide.md:374-391; "compacted/tombstone records remain truthful").
  2. Retrying X via TUI recomputes the identical content digest (unchanged inputs) → alias conflict → `Existing=true` → "matching durable operation already exists" (`app.go:245-250`) — the operator cannot start X via TUI until the alias cascades away with run deletion (~37 days at default retention: FullHistory 7d + Tombstone 30d, runcontrol/model.go:423-424).
- **Counter-evidence searched**: web door unaffected (token-bound dedup); CLI has no study-cancel command; no TUI test covers `beginOperation`/`StudyCancel` (grep: zero hits) so nothing pins this as intended.
- **Regression test**: the preserved repro (`stale_confirmation_repro_test.go`) asserts accepted kind ≠ executed kind. Fix shape: derive acceptance from `req` (re-prepare or require `req == Confirmation.Request.Kind/scope`), else skip durable acceptance.

## F2 · MEDIUM severity, HIGH confidence — readOnly composition split makes TUI the only door whose dashboard passively rewrites governed files, clobbering concurrent writers and cross-door invalidating QA fingerprints

- **Claim**: serve forces `readOnly:true` twice (`serve_commands.go:59`, `web_usecases.go:429`) → `sprintService().WithoutStatusWrites()` (`usecases.go:130-132`) suppresses writes; TUI composes without it (`tui_commands.go:41-46`).
- **Path**: every Dashboard load, `r` refresh, and 1 Hz run-view tick (`app.go:222-226, 271-273`) → `SprintSummaries` → `Status` per sprint (`sprint_usecases.go:482`) → unconditional `SaveFlowState` (`sprint/service.go:291-295`), which always rewrites bytes (`UpdatedAt = time.Now()`, `sprint/state.go:247`). No cross-process lock exists (only atomic temp+rename, state.go:259-290).
- **Observable bad outcomes**:
  1. Last-writer-wins lost updates against concurrent CLI/web processes writing flow-state.json (e.g., a review/smoke publication landing between Status's load and save is silently reverted until the next writer).
  2. `flow-state.json` is a governed fingerprint input for all QA kinds (`operations.go:678-685`); an open TUI changes its bytes every second, so a QA prepare→confirm sequence done elsewhere fails with `stale_confirmation` despite zero semantic change — cross-door interference caused purely by an idle dashboard.
  3. Contract contradiction: top-level help says "Open a read-only terminal dashboard" (`app.go:268`) while `tuiHelp` discloses status rewrites (`tui_commands.go:90`).
- **Regression test**: compose TUI use cases, call Dashboard twice, assert flow-state.json mtime/content unchanged (fails today; passes if TUI adopts `readOnly:true` or Status gates on content diff).

## F3 · MEDIUM severity, MEDIUM confidence — study-cancel converts workspace-file content (lock JSON PID) into a signal via liveness-only validation

- **Claim**: `study.CancelRunLoop` (`internal/study/locks.go:141-159`) reads `studies/<s>/.ultraplan/run-loop.lock`, checks only `processAlive(pid)` (`kill 0`) and the recorded study name, then `syscall.Kill(pid, SIGINT)`. No process-identity verification, unlike the careful `ProcessIdentity{HostDigest, BootID, BirthToken}` regime run-control uses for leases (`runcontrol/model.go:193-210`).
- **Trust transition / misuse**: anyone who can write workspace files (workspace sync, collaborator artifacts, malicious tooling) can place `{"pid":N,"study":"<name>"}` and have any operator door — TUI `c`, web `kind=study-cancel` (`operation_runner.go:152-162`) — SIGINT arbitrary same-UID process N. Independently, legitimate PID reuse makes `RunLoopActive` report a dead owner as live: cancel signals the innocent new process, and acquire false-reports "held by pid N".
- **Consequence**: limited (SIGINT to same-UID processes) but a genuine file-content→syscall primitive crossing the codebase's own governed-input hostility assumptions (symlink rejection, `displaySafe` redaction exist precisely because workspace content is treated as untrusted).
- **Regression test**: write lock with PID of a spawned dummy process, invoke OperationStudyCancel through `RunOperation`, assert foreign process signaled (fails today); fix: record and verify `/proc` cmdline prefix + start tick like run-control identity.

## F4 · LOW-MEDIUM — replay semantics diverge: CLI `run follow` silently serves post-compaction partial history where web enforces `replay_gap`

`repository.Events` returns only the retained tail with no gap signal (`runcontrol/sqlite.go:819-821`). Web durable fallback rejects `after+1 < OldestRetainedSequence` with `replay_gap` and cursor-ahead conflicts (`operation_handlers.go:455-461`; REST equivalent in run_handlers.go), but `run follow` (`run_commands.go:161-195`) prints whatever remains and exits 0 — an operator auditing a compacted run believes they captured the full journal. Same logical observation, opposite failure visibility.

## F5 · LOW — operations cancel endpoint skips the `Target.Kind=="operation"` gate its sibling projections enforce

`handleOperationStatus`/`durableOperationStatus`/`followDurableOperationEvents` all require `Target.Kind=="operation"` (`operation_handlers.go:364, 416, 452`), but both cancel handlers fall back to `runs.CancelRun(id)` for **any** run id (`:206-213, 381-396`), cancelling non-operation runs and echoing their kind/reason/state. Mitigated: `DELETE /api/v1/runs/{id}` grants the same power by design (run_handlers.go:918-928) — parity defect, not privilege escalation.

## F6 · LOW — identifier sanitization gaps reach raw terminal sinks; Windows path redaction literal can never match

`Target.Validate` and `safeEventValue` reject only NUL/CR/LF (`runcontrol/model.go:186`, `sanitize.go:108`) — ESC passes; web transport never charset-validates `options.stage/task/shard` (`mapOperationRequest` validates scope only). Persisted Stage/Task render unescaped via `fmt.Fprintf` in `renderRunSnapshot` (`run_commands.go:416-435`) and `run follow` (`:172`), enabling ANSI escape injection from durable values into operator terminals (local-process attacker today; governed-file-derived task ids are the realistic remote-content vector). Also `safeProjectedText` redacts `` `C:\\Users\\` `` (double backslashes, `web/operations.go:647`) which matches no real Windows path.
