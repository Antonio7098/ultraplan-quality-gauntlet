## Finding 1 — Override rationale accepted by both transition gates is rejected by flow-state persistence, after canonical smoke.md was already committed

- **Claim**: The Verify diagnostic-continuation ladder and the smoke review gate accept override rationales the durable-state validator rejects — and the rejection happens *after* the artifact write.
- **Bad outcome** (reproduced): `sprint p s verify --to smoke --force-review --override-reason $'line1\nline2'` (or any rationale >240 bytes) runs the full authoring+discovery harness work, atomically commits a new canonical `smoke.md` containing the raw multi-line rationale, then fails with `smoke_reconciliation` because `validateSmokeStageState` rejects `\n`/`>240` in `Override.Rationale`. Result: artifact/state divergence (no `LastComplete`, no `Override` persisted), prior fresh smoke evidence invalidated ("smoke artifact digest changed" → assessment flips incomplete), and a terminal attempt recorded as completed with no evidence behind it.
- **Trigger/preconditions**: fresh failing review + confirmed override (`--yes`) + harness mapping resolving blocked/not-applicable — the only `commitSmoke` path reachable while `DiagnosticOnly=true` (smoke.go:128-135).
- **Evidence path**: gates check only non-blank rationale (verify.go:74; smoke_protocol.go:204; CLI parse adds nothing, sprint_commands.go:1235) → rendered verbatim via `printable()`, which preserves newlines (smoke.go:488) → `ValidateSmokeContent` passes → `atomicWriteFile` (smoke.go:448) → `SaveFlowState` fails on smoke_types.go:318. Repro tests: `TestGauntletOverrideRationaleMultilineBreaksStatePersistence`, `TestGauntletOverrideRationaleTooLongBreaksStatePersistence`, control `...ShortSucceeds`, and end-to-end through the surface itself: `TestGauntletVerifyTransitionHitsDivergenceDirectly`.
- **Controls/counter-evidence**: failure is loud (ExitValidation), atomic write keeps recovery possible, short rationales persist fine — so this is an unvalidated-input gap, not systematic corruption. But it contradicts requirements.md:74 ("failed or interrupted runs must not corrupt the last complete Markdown artifacts"): the failed run did replace the last complete smoke.md.
- **Severity**: medium. **Confidence**: high.
- **Fix/regression**: validate rationale shape (single line ≤240 bytes, or relax the state validator) at parse/`prepareSmokeStatic` time; keep my three repro tests as regressions.

## Finding 2 — Governed-input changes do not stale completed review evidence; `verify --to smoke` promotes on superseded scope

- **Claim**: With `strictCompletedReviewSnapshotFreshness=false` / `strictCompletedSmokeSnapshotFreshness=false` (freshness_policy.go:11-14), only direct edits to review.md/smoke.md invalidate evidence. A change to requirements/plan/execute/target after a passing review leaves it `Fresh`, so `Verify` reuses it (verify.go:65) without rerun and completes promotion including roadmap delivery reconciliation.
- **Reproduced**: `TestGauntletGovernedInputChangeDoesNotForceReviewRerun` — after editing `requirements.md` post-pass: `reviewFresh=true assessment=pass`; `Service.Verify(To=smoke)` returns nil with `ReviewResult==nil` (no rerun) and proceeds to delivery reconciliation. Sprint 28 requirements.md AC43 and constraint 73 promise exactly this staleness for "governed planning inputs … target implementation identity".
- **Counter-evidence (stated deliberately)**: the disablement is documented as intentional and temporary in freshness_policy.go and docs/local-web.md:265-273, and smoke_test.go:471-474 pins non-staling for external evidence edits. This reads as an adjudicated product decision — but no workspace artifact re-adjudicates AC43, and the shipped behavior materially weakens this boundary's core guarantee (a requirements/plan edit is not the "small concurrent edit" case the policy comment cites).
- **Severity**: medium-high as a contract-conformance gap. **Confidence**: high on behavior, medium on adjudication status.
- **Recommendation**: scope snapshot freshness to contract-defining inputs (requirements/plan/target identity) even if whole-tree hashing stays off, or amend the sprint contract explicitly.

## Finding 3 — Diagnostic-only completions are durably recorded as `completed` executions with no evidence

When the override forces `DiagnosticOnly`, `runSmoke` returns before `commitSmoke` (smoke.go:180-182), yet the terminal `saveSmokeAttempt` persists `Status=completed` with empty verdict, no `LastComplete`, no digest (reproduced: `TestGauntletDiagnosticCompletionRecordsCompletedWithoutArtifact`; status then reports `execution_status=completed`). Canonical assessment stays fail-safe; this corrupts status display and attempt semantics only. Severity low, confidence high. Fix: record such attempts as a distinct diagnostic/blocked category rather than `SmokeCompleted`.
