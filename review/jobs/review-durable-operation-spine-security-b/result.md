# Findings — `durable-operation-spine` (adversarial security review)

## F1. TUI alias digest is content-only → independent confirmations collide; repeat operations permanently blocked
**Severity Medium · Confidence High (reproduced)**

1. **Claim**: `tui/app.go:236-238` derives the accept digest as `sha256(CanonicalRequest + "\0" + InputFingerprint)`. Both inputs are deterministic functions of the request and governed inputs (`operations.go:360-372`), so two *unrelated* confirmations of identical inputs produce the identical alias.
2. **Bad outcome**: a second, legitimate run can never start. Reproduced: `PrepareOperation` twice on an unchanged workspace → identical digests (`8db0a831f44f…`); after finishing the first accepted run, a second `AcceptOperation` returns `Existing=true, Lifecycle="succeeded"` pointing at the old run; TUI renders "matching durable operation already exists".
3. **Trigger**: re-confirm any runtime operation from TUI while `governedOperationInputs` are byte-identical. Review/smoke/execute writes (review.md, smoke artifacts, target tree, execute `.run-state.json`) are **not** governed inputs, so ordinary post-run state changes don't rotate the fingerprint — this is the common case, not an edge case.
4. **Evidence path**: `beginOperation` → `AcceptOperation(digest)` → `operation_aliases` unique constraint (`runcontrol/sqlite.go:449-454`) → `ErrConflict` → `ResolveOperationAlias` → Existing card (`durable_operations.go:106-112`).
5. **Counter-evidence checked**: web is immune — digest = `sha256(session+"\0"+token)` with a fresh token minted per confirmation (`security.go:404-411,448-451`); CLI is immune — empty digest writes no alias row (`sqlite.go:445`). `durable_operations_test.go:92-124` pins cross-*manager* dedup semantics but nothing pins TUI derivation. No contract justifies collapsing separate confirmations; web's double-submit protection comes from single-use tokens, not content dedup.
6. **Regression test**: prepare→accept→finish, then prepare again unchanged → second accept must start a fresh run. Fix direction: per-confirmation nonce in the digest (web parity) or ignore terminal aliases during resolution.

## F2. Cancellation racing pending coalesced omissions is durably recorded as `persistence_degraded`
**Severity Medium · Confidence High (reproduced)**

1. **Claim**: `run_control.go:303-315` flushes trailing coalesced omissions on the already-cancelled `runCtx`; the resulting context error is stored as `persistenceErr`, which short-circuits `terminalOutcome` (:322-331) and proposes `TerminalPersistenceLost` on a detached context that succeeds against a healthy DB.
2. **Bad outcome** (reproduced): user cancellation persisted as `outcome="persistence_degraded", reason="durable event persistence failed"`, while the returned error still wraps `context.Canceled` — so live hub/TUI status says *cancelled* while the canonical journal says *persistence lost* (split-brain). During `drainAndWait` shutdown every active runtime run with a pending omission writes a bogus degraded terminal, training operators to ignore real persistence incidents.
3. **Trigger**: ≥2 identical progress events within the 250 ms window at the moment of parent cancellation (Ctrl-C, hub cancel, server drain).
4. **Evidence**: flush uses `runCtx` (:305) vs. the invariant's own detached-terminal discipline (:323, :335) and manager tier's correct detached caller ctx (`durable_operations.go:276`). No test covers this path.
5. **Regression test**: stub base emits duplicate progress then honors cancel; assert terminal == cancelled and no `persistence_degraded` proposal. Fix: flush on `context.WithoutCancel(ctx)` + bounded timeout, or skip when only ctx cancellation failed.

## F3. Manager-tier control failure silently kills the operation and records plain "cancelled"
**Severity Low-Medium · Confidence High (reproduced)**

1. **Claim**: `controlOperation` cancels on the first `Snapshot`/`AcknowledgeCancellation`/`Heartbeat`/`Reconcile` error with no diagnostic event and no surfaced error (`durable_operations.go:235-261`); heartbeat/snapshot are single-shot — no retry wrapper, unlike appends' 5 s retry.
2. **Bad outcome** (reproduced): injected snapshot outage → operation context cancelled within one tick; journal contains exactly `[lifecycle, terminal]` with reason "operation cancelled" — indistinguishable from a user cancel, and a transient DB hiccup destroys long-running work. The runtime tier by contrast records the cause and proposes `persistence_lost` (`run_control.go:263-298`) — asymmetric detectability vs. TRD L2223/L2367.
3. **Regression test**: flaky repository → assert a warning/diagnostic event is persisted or finish maps away from plain-cancelled.

## Defended non-issues (hypothesized, then refuted)

- **Fingerprint TOCTOU bypass**: transport DTOs carry no fingerprint field (`startRequest`/forms); `consume()` enforces stored-vs-fresh fingerprint (`security.go:431-434`); `RunOperation` re-checks `prepared.Request.ExpectedFingerprint` — TUI passes `Confirmation.Request` which carries it (`tui/app.go:104,155`), pinned by `web_operations_test.go`. Empty-expected skip is unreachable from all three adapters. TUI study-cancel skips acceptance, but it is non-runtime control-plane, consistent with CLI posture.
- **Secret exfiltration via payload keys** (e.g., `api-key` slipping the app denylist): neutralized downstream — storage gate is an allowlist + value markers + absolute-path rejection applied to every append (`sqlite.go:617`, `sanitize.go:10-61,90-104`).
- **Empty CLI digest collisions**: no alias row written for empty alias (`sqlite.go:445`).
- **Degrade-mode cancel storm**: `ErrWebUnavailable` forwarding is uniform across all three manager methods (`usecases.go:103-120`, `web_usecases.go:444-491`), so the hub's tolerance is coherent.
- **Retention parse-error fallback**: zero policy values get safe defaults (`retention.go:14-29`).
- **Target-field injection from CLI args** (`study_commands.go:814` concatenation): `Target.Validate` bounds and rejects NUL/CR/LF (`model.go:172-191`); web scope charset validated at decoder and in `PrepareOperation`.
- **QA writer-token handoff**: possession-of-context authority is explicit; struct equality + monotonic generation fencing; post-terminal heartbeat rejection is intended fencing, not a flaw.
