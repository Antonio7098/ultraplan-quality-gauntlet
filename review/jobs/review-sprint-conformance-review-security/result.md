# Findings — `sprint-conformance-review` (security/misuse lens)

## F1. Model-authored finding text trips the artifact placeholder validator and deterministically bricks the review stage — PROVEN

**Severity:** high (reliability/availability of the governance gate) · **Confidence:** high (reproduced)

- **Claim:** `ValidateReviewContent` runs `containsPlaceholder(content)` over the entire rendered `review.md` (review.go:1111), including reviewer-controlled finding Title/Detail/Action rendered verbatim (review.go:1084-1089). `containsPlaceholder` flags the case-insensitive substrings `"todo"`, `"tbd"`, `"<placeholder"`, and `{{Ident}}` (index.go:218-221). Any valid, verdict-contributing finding whose prose contains these extremely common engineering words makes the whole run fail after full reviewer spend.
- **Observable bad outcome:** reproduced against the real code: a finding with Detail `"…tracked by a TODO in config.go."` yields `status=failed`, `err="generated review.md failed validation"`, diagnostic `artifact-invalid: empty or placeholder review`, **no review.md written**; an otherwise identical control finding completes with `pass_with_findings`. Every retry re-runs all reviewers and reproduces unless the model rephrases. Even a genuine `fail` verdict loses its synthesized artifact (render/validate at review.go:614-620 precedes the fail return at 640), contradicting protocol Stop Conditions ("Return fail, with a synthesized review where possible").
- **Trigger/preconditions:** one schema/citation-valid applicable finding whose text contains a trigger substring. Sources: reviewer LLM output (declared untrusted, §6 pack), steerable by anyone influencing governed inputs or target code (which legitimately contains TODO markers reviewers will report).
- **Evidence:** review.go:615-619, 1080-1091, 1110-1113; index.go:10, 218-221; no sanitization between JSON decode and render. Proof test: `/tmp/opencode/upgo-proof/internal/sprint/zzz_gauntlet_proof_test.go`.
- **Execution path:** `runReviewer` → valid result → `validateReviewCoverage` verdict `pass_with_findings` → `RenderReviewMarkdown` → `ValidateReviewContent` → `containsPlaceholder` ⇒ true ⇒ `persistReviewFailure("generated review.md failed validation")`.
- **Controls/counter-evidence:** none — `reviewResultProblems` does not filter placeholder tokens; fixtures only ever use "Follow-up"/"Small issue" so tests never trip it.
- **Fix/regression:** scope the placeholder check to the deterministic scaffolding (fixed header/footer lines) or strip finding/diagnostic text before the check. Regression: full `Review` with a valid medium finding containing "TODO"/"TBD" must complete and write the artifact.

## F2. Changed-target containment is lexical-only: symlinked evidence paths exfiltrate arbitrary readable files into reviewer prompts and the snapshot cache — PROVEN

**Severity:** high (security) · **Confidence:** high mechanism / medium end-to-end likelihood

- **Claim:** `PrepareReview`'s changed-path loop (review.go:350-367) checks `inside(manifest.Target, full)` (lexical `filepath.Rel`, artifacts.go:77-83) then `os.ReadFile(full)` directly. Symlinks inside the approved target pointing outside the workspace pass the check and their referent content enters the manifest. The codebase's own convention elsewhere rejects exactly this: `targetIdentity` does `Lstat` + `EvalSymlinks` + `inside` with error "target symlink escapes" (verify.go:405-428); `qa_state.go`, `prompt_context.go`, `smoke_protocol.go` do the same.
- **Observable bad outcome:** reproduced: symlink `<target>/docs/release-notes.md → /outside-secret.txt` named in actor-editable `.run-state.json` `files[]` produces **zero preflight findings**, places the outside file's bytes into `manifest.Contents["target/docs/release-notes.md"]`, and embeds them **verbatim into every reviewer prompt** (`secretEmbeddedInReviewerPrompt=true`). Consequences: (a) arbitrary process-readable file contents transmitted to the external LLM provider; (b) content persisted mode-0400 under `.ultra/cache/review/<project>/<sprint>/<fp>/target/...` and retained whenever the run ends blocked/failed/cancelled (RemoveAll only at review.go:638); (c) citations against it are *valid*, so reviewers can quote secret lines into `review.md`, which `publishReviewStage` commits to git (publication.go:84-89); (d) fingerprint poisoned with attacker-chosen reads. Secondary effect: an evidence path naming a FIFO blocks `PrepareReview` indefinitely pre-lease (plain blocking `ReadFile`, no timeout).
- **Trigger/preconditions:** execute-stage agent (controls evidence paths via artifact URIs, execute.go:305 / `safeRelPath` is lexical-only, execute_state.go:263-280, 275-281), a committed symlink materialized into the git worktree, or any post-check TOCTOU plant. No cross-check against actual worktree diffs exists — any contained readable path can be declared "changed".
- **Evidence:** review.go:347-367, 1397-1443; artifacts.go:77-83; proof test `/tmp/opencode/upgo-proof/internal/sprint/zzz_gauntlet_symlink_test.go`.
- **Controls/counter-evidence:** governed-path exclusion and lexical containment exist and fire for plain traversal (`../` fails `Clean`+`inside`) — the design intent "escapes become preflight findings" (pack §6) is implemented lexically only; symlink case falls through.
- **Fix/regression:** `Lstat` each resolved changed path; require regular files, or resolve with `EvalSymlinks` + `inside(target)` mirroring verify.go:405-428. Regression: fixture with escaping target symlink + evidence path naming it ⇒ preflight finding emitted, `manifest.Contents` free of outside bytes.

## F3. Contract-required "absence of smoke claims" validation is not implemented

**Severity:** low-medium (artifact integrity vs CURRENT-CONTRACT) · **Confidence:** high (gap certain; consequence bounded)

- **Claim:** review-sprint-protocol.md §6 (workspace @ ab12dc38, line 76) requires the validator to check "absence of smoke claims"; TRD §18.6 lists the same bullet. `ValidateReviewContent` (review.go:1109-1137) checks sections, fingerprint, verdict enum, coverage ids, placeholders — nothing rejects smoke-result claims, and grep finds no such check anywhere in the review path.
- **Bad outcome:** a reviewer finding titled e.g. "smoke suite passed on CI" renders into the canonical `review.md` Findings section and passes `ultraplan validate review`; the unverified operational claim is published via gitpublish and consumed by humans/downstream readers, defeating the protocol's stage-ordering disclosure rule.
- **Trigger:** model emits such text (prompt-injectable through governed inputs).
- **Fix/regression:** add a deterministic check rejecting smoke-outcome phrasing in finding/diagnostic text; regression test asserting `ValidateReviewContent` flags it.

## F4. Reviewer-panic diagnostic bypasses the mandatory redaction/truncation boundary

**Severity:** low · **Confidence:** high

- **Claim:** every `out.Error` assignment in `runReviewer` wraps through `safeReviewText` except the panic recover (review.go:888): `fmt.Sprintf("reviewer panic: %v", r)` is raw. It flows unredacted/untruncated into `reviewer-failed` diagnostics (review_runtime_validation path, review.go:1011 uses `Message: r.Error` verbatim), `flow-state.json` Diagnostics, CLI `--json`, and progress callbacks. All other diagnostics pass `safeReviewText`/`safeError` (NUL/CR/LF strip, ~180-char truncation, `config.RedactValue`, root elision); attempt-level strings do get `safeError` (review.go:1265-1271), so the breach is limited to stage-state/CLI surfaces. Panic values from deep stacks can embed absolute paths/user names/request fragments.
- **Fix/regression:** wrap the recover with `safeReviewText(s.root, fmt.Sprintf(...))`; unit-test a panicking runtime asserts no workspace root in stored diagnostics.
