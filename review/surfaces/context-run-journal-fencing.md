# Context Pack: `run-journal-fencing` — Run-control SQLite journal and fencing

Target: ultraplan-go @ 8eef70f4903b25580719960009a170945bdad9ad (frozen; working tree differs only in internal/sprint smoke files, runcontrol+app identical).
Planning context: ultraplan-workspace @ ab12dc38059c9bf485f9aced9075bcd7d924cac5.
Domain: durability-core. Risk: critical. Descriptive only — no defect judgments.

## 1. Purpose

`internal/runcontrol` is the durable identity and arbitration layer for every executing UltraPlan operation (doc.go:1-6). It records: the accepted execution (`runs`), at most one fenced owner attempt per run (`attempts`), a strictly ordered append-only sanitized event journal (`events`), optional operation alias identities for dedup (`operation_aliases`), and reconciliation decision evidence (`reconciliation_log`) — all in one private SQLite database at `.ultraplan/run-control.db`. It deliberately does NOT own product workflow state, artifacts, or runtime supervision (doc.go, interfaces.go:47-48). Core mechanisms: accept-before-execute; fenced claim with lease + heartbeat; cancellation request/acknowledge split across processes; single-winner terminal compare-and-set over seven outcomes including explicit uncertainty (`cleanup_uncertain`, `persistence_degraded`); conservative birth-identity reconciliation that never infers success.

## 2. Entrypoints and control flow

### 2.1 Open path (`sqlite.go:60-134`)
`OpenSQLite(ctx, workspaceRoot, SQLiteOptions)`: validate workspace root (abs, dir, sqlite.go:136-152) → prepare private storage (`preparePrivateDatabase`, :154-191): `.ultraplan/` created 0700, symlink/non-dir rejected via Lstat (:159-165); `run-control.db` created `O_CREATE|O_EXCL|O_RDWR` 0600, symlink/non-regular rejected (:172-186); `enforcePrivateMode` chmods then re-stats to verify exact mode (:193-205) → open DSN with fixed pragmas `_busy_timeout=5000 _foreign_keys=on _journal_mode=WAL _synchronous=FULL _txlock=immediate _defensive=1` (:73-80) → ping, then `verifyPragmas` reads back journal_mode/synchronous/foreign_keys/busy_timeout only (:207-227) → `migrateSchema` (migration.go:25-82; current-version DBs take the lock-free verify path — schema record equality + integrity check; migration itself belongs to surface `run-recovery-retention`) → connection pool default 4, operator-cappable 1..16 (:92-100) → repository assembled with injected-or-wall Clock, RandomIDSource, normalized retention policy (:107-131).

### 2.2 Accept (`sqlite.go:378-470`)
Quota gates first: `storageBytes()` sums sizes of all regular files whose names start with `run-control.db` in `.ultraplan/` (retention.go:35-56 — includes `-wal`/`-shm`/`.migrate.lock`/backups); usage ≥ 80% of hard quota triggers inline `Compact(ctx,64)` (:384-390); usage ≥ soft quota (hard − 16 MiB headroom) refuses acceptance with retryable `CodeQuota` (:391-395). Then Target/Correlation validation, ProductStatus/ConfirmationDigest ≤ MaxSafeValueBytes (:396-404), RunID minted when absent and validated (:405-415), correlation marshaled bounded to 256 KiB (:416). One immediate transaction inserts the `runs` row (lifecycle `accepted`, liveness `unknown`, record_state `full`, cancellation_state `none`, last_sequence 0) (:429-444); duplicate RunID → typed Conflict (:440-442). Optional OperationAlias inserts an `operation_aliases` row in the same tx; alias conflict → Conflict (:445-455). Snapshot loaded + validated inside the tx before commit (:456-462). NOTE: Accept writes NO event row; the journal stays empty until the first cancellation/append/terminal/reconcile write.

### 2.3 Claim (`sqlite.go:486-592`)
Validates RunID/Owner/Correlation/Lease>0 and AttemptID (minted when absent) (:490-512). In one immediate transaction: read lifecycle+current_attempt (:529); terminal run → `CodeTerminal`; existing current attempt → `CodeConflict` "run already has a current owner attempt" (:533-538). Next lifecycle = running, preserved as cancelling if already cancelling (:539-542). Ordinal = MAX(ordinal)+1 and fencing_generation = MAX(fencing_generation)+1 over the run's attempts (:543-546); attempts table enforces `UNIQUE(run_id,ordinal)` and `UNIQUE(run_id,fencing_generation)` (:288-289) plus `fencing_generation > 0` (:278). INSERT attempt (owner_id, host_digest, boot_id, pid, process_birth_token, claimed_at=heartbeat_at=now, lease_expires_at=now+lease) (:547-560), then CAS-style UPDATE of runs: `SET current_attempt_id=?, lifecycle=?, liveness='live', started_at=COALESCE(started_at,?), updated_at=? WHERE run_id=? AND current_attempt_id IS NULL AND terminal_outcome IS NULL`; RowsAffected ≠ 1 → Conflict (:561-571). Snapshot validated pre-commit. Because no code path ever nulls `current_attempt_id`, each run is claimed AT MOST once in its lifetime (grep over package: only setter is sqlite.go:563; reconcile paths require it NULL/non-terminal).

### 2.4 Append (`sqlite.go:608-711`)
Fence validated (RunID+AttemptID grammar, OwnerID non-empty, generation > 0; model.go:287-298) → draft normalized (typed fields copied into payload, model.go:490-505) and sanitized (§6) → hard-quota gate: usage ≥ hard quota rejects all event types except reserved ones (lifecycle/warning/cancellation/recovery/terminal/omission, :618-622, :713-720) → draft validation (:1005-1029: known type/scope, active-only lifecycle hint, stage/task ≤512 bytes without NUL/CR/LF, payload keys ≤128 bytes/values ≤32 KiB without NUL, omission needs positive count). Immediate transaction: `verifyFence` (:985-1003 — attempt row must exist for (run_id, attempt_id), owner_id and fencing_generation must match, and runs.current_attempt_id must equal the fence's attempt) → read last_sequence+lifecycle; terminal run → `CodeTerminal` immutable (:652-658); lifecycle hint must satisfy `validActiveTransition` (:1031-1047: accepted→{queued,running,cancelling}, queued→{running,cancelling}, running→cancelling, cancelling→nothing, self-transitions allowed) → sequence = last_sequence+1 inserted into events (:666-672) → CAS UPDATE runs: `SET last_sequence=?, lifecycle=?, omission_total += ?, updated_at=? WHERE run_id=? AND last_sequence=? AND current_attempt_id=? AND terminal_outcome IS NULL`; RowsAffected ≠ 1 → `CodeStaleFence` "event writer lost its authoritative fence" (:677-686) → inline `compactRunJournal` when the run exceeds 4096 events or 16 MiB retained payload bytes: deletes oldest progress/message/omission events (never the just-written sequence), sets record_state=compacted, history_complete=0, oldest_retained_sequence=MIN(sequence) or last+1; nothing removable → typed `CodeQuota` failure (retention.go:58-95) → snapshot validated, commit, notify (no-op unless Notifier wired; production wires none), debug log.

### 2.5 Heartbeat (`lifecycle.go:14-68`)
Lease > 0 required; hard-quota gate REFUSES heartbeats at ≥ hard quota ("hard quota requires the owner to stop active work", :24-28). Immediate transaction: verifyFence → CAS UPDATE attempts `SET heartbeat_at=?, lease_expires_at=now+lease WHERE ... AND outcome IS NULL` (RowsAffected≠1 → StaleFence) → CAS UPDATE runs liveness='live' where current attempt matches and not terminal (RowsAffected≠1 → StaleFence) → snapshot, commit, metric. Heartbeat both extends the lease and clears a prior `stalled` marking.

### 2.6 Cancellation request / acknowledge split
- RequestCancellation (`lifecycle.go:70-134`): reason trimmed, must be non-empty, ≤32 KiB, no NUL/CR/LF (:77-80); CLI additionally whitelists {user_requested, operator_requested, shutdown_requested, quota_exceeded} (run_commands.go:394-401). No fence required — works ownerless. Idempotent short-circuit: already terminal OR any non-none cancellation state returns (current snapshot, changed=false) after committing the read tx (:91-96). Otherwise inserts a `cancellation` event (attempt_id nullable — set only when a current attempt exists, :102-109) and CAS UPDATEs runs: `SET lifecycle='cancelling', cancellation_state='requested', reason, requested_at, updated_at, last_sequence=? WHERE run_id=? AND terminal_outcome IS NULL AND cancellation_state='none' AND last_sequence=?` (:110-120); lost race → retryable Conflict.
- AcknowledgeCancellation (`lifecycle.go:136-194`): fence-gated. Short-circuits (changed=false) when terminal or already acknowledged; state ≠ requested → Conflict; else inserts an ack `cancellation` event and CAS UPDATEs `cancellation_state='acknowledged', acknowledged_at` guarded by current_attempt match + state=requested + unchanged last_sequence (:156-181).
- `cancellation_state='uncertain'` exists in the schema enum and Health projection but no code path writes it (grep: only model.go definition + Health count sqlite.go:877).

### 2.7 ProposeTerminal (`sqlite.go:722-807`)
The ONLY writer of terminal state (plus reconcileUnclaimed below). Validated proposal (outcome ∈ closed 7-value enum, reason/proposer bounded, :731-736). Immediate transaction: verifyFence → loadSnapshot; if Terminal already present, COMMIT the read tx and return (winner, won=false, nil) — losers observe the incumbent outcome instead of erroring (:753-758). Winner path: insert one `terminal` event at last_sequence+1 (payload {outcome,reason}) (:759-768), then CAS UPDATE runs setting lifecycle=outcome.Lifecycle(), liveness='terminal', finished_at, last_sequence, terminal_* columns `WHERE run_id=? AND current_attempt_id=? AND terminal_outcome IS NULL`; RowsAffected ≠ 1 → StaleFence loser (:769-786); attempts.outcome stamped on the winner's own attempt (:787-790); snapshot validated against the full terminal-consistency rules (model.go:355-364) before commit. Schema CHECK ties terminal_outcome ↔ finished_at ↔ terminal lifecycle (:268-269).

### 2.8 Reconcile (`lifecycle.go:301-416`)
Runs on every repository open (app/run_control.go:66) and every 10 s inside active-operation control loops. Grace defaults to ReconciliationGrace=45 s; batch default 64/max 256. Pass 1 — unclaimed runs (`current_attempt_id IS NULL AND accepted_at older than grace`, :320-339): `reconcileUnclaimed` (:427-479) re-checks state in-tx, inserts one `terminal` event (attempt_id NULL) and CAS-terminalizes to interrupted/"owner_never_claimed_after_grace" guarded by `current_attempt_id IS NULL AND terminal_outcome IS NULL`; concurrent claim/win → silent no-op. Pass 2 — expired owners (runs joined to their current attempt where lease_expires_at older than grace, :360-383): probe recorded PID via ProcessProbe; `reconcileProcessDecision` matrix (:481-495):
- ErrProcessNotFound → interrupted, "owner_process_missing_after_grace";
- other probe error → cleanup_uncertain, "owner_process_identity_uncertain_after_grace";
- incomplete stored OR observed identity fields → cleanup_uncertain;
- exact field mismatch (host/boot/pid/birth) → interrupted, "owner_process_birth_mismatch_after_grace";
- exact live match → NO terminal: markStalled only (:497-509, liveness='stalled' CAS on still-current attempt; StaleFence tolerated).
Terminal proposals ride the DEAD attempt's own recorded fence (ProposedBy="reconciler"); ErrTerminal/ErrStaleFence from racing writers are tolerated (:392, :401). Every decision appended to reconciliation_log via recordReconciliation (:511-527; evidence reduced to class strings safe_identity_only / acceptance_timestamp_only; errors deliberately ignored by callers `_ = r.recordReconciliation(...)` :352, :411). Report counters Scanned/Terminal/Stalled/Uncertain + decisions list. Linux probe reads `/proc/<pid>/stat` starttime (field after last ')' index 19) as BirthToken + `/proc/sys/kernel/random/boot_id` as BootID + sha256(hostname)[:16] as HostDigest (process_linux.go:16-45, process.go:47-51); darwin uses sysctl kinfo start time + kern.boottime (process_darwin.go); other platforms return partial identity + ErrProcessIdentityUnavailable (process_other.go:16-18). PID ≤ 0 rejected. `NewProcessOwner` mints a random `own_…` ID and self-probes, tolerating identity unavailability by keeping PID only (process.go:30-45). Expiry comparisons use SQLite's clock in production: `julianday(col) <= julianday('now', '-<grace> seconds')` vs bound parameters when a Clock is injected (tests only; sqlite.go:1132-1144). Clock-jump safety pinned by test (backward jump never expires early, forward jump reconciles).

## 5. Invariants (as implemented)

- Identity grammar: RunID/AttemptID are `run_`/`att_` + 26 lowercase canonical base32 chars = exactly 128 bits (id.go:73-89); validated at every entry point; generated via crypto/rand.
- Single owner per run lifetime: claim requires `current_attempt_id IS NULL`; nothing ever clears it; late claims hit CodeConflict (live) or CodeTerminal (terminal).
- Fencing: every mutation by an owner goes through verifyFence (attempt row + owner + generation + runs.current_attempt_id agreement) plus per-statement CAS guards (last_sequence for Append/Ack/Cancel; terminal_outcome IS NULL everywhere; outcome IS NULL on heartbeat attempts-row update). Stale writers get typed CodeStaleFence, never silent success.
- Monotonic journal: sequences allocated as MAX+1 inside immediate transactions; immutability trigger blocks UPDATE; compaction only DELETEs non-authoritative types (progress/message/omission; tombstone adds accepted/claimed/lifecycle/recovery) and advances oldest_retained_sequence + history_complete=0 so readers can detect gaps.
- Single-winner terminal: one CAS-guarded transition; later proposers receive (incumbent, won=false); append-after-terminal CodeTerminal; request-cancellation-after-terminal idempotent no-op returning the winner; completion may win AFTER requested cancellation (test-pinned) leaving cancellation_state='requested' frozen beside a succeeded terminal.
- Active-state machine: validActiveTransition grammar; 'cancelling' absorbing among active states; terminal reachable only through the two arbitration paths.
- Cancellation request/acknowledge split: request is ownerless and idempotent; acknowledge is fenced; states none→requested→acknowledged ('uncertain' reserved/unwritten).
- Conservative liveness: stall (exact live identity + expired lease) never terminalizes; interrupted requires missing process or exact birth mismatch; anything unprovable → cleanup_uncertain; success is NEVER inferred by reconciliation.
- Quota/liveness coupling: soft gate pauses new accepts (retryable), hard gate blocks non-reserved appends and heartbeats while always permitting reserved recovery types (lifecycle/warning/cancellation/recovery/terminal/omission).
- Boundedness: target fields 512 B; safe values 32 KiB; correlations ≤256 KiB encoded; payloads ≤256 KiB; whole sanitized draft ≤128 KiB else replaced by a warning stub carrying omission metadata; per-run journal ≤4096 events/16 MiB; reconciliation evidence ≤16 KiB; log line ≤4 KiB/file ≤1 MiB; support export ≤1 MiB.
- Durability posture: WAL + synchronous FULL + immediate transactions on every mutation; busy_timeout 5 s; four pragmas verified at open; chmod-verified 0700/0600 private modes; symlink/non-regular rejection at directory, database, and log layers.
- Time authority: production expiry math executes inside SQLite so all processes share the database clock; injected clocks swap to parameter comparison (tests only — no production injector exists, map-02 X6).
- Typed error taxonomy with Retryable flags; SQLITE_BUSY/LOCKED→busy(retryable), PERM/READONLY→permission, CORRUPT/NOTADB→corrupt, FULL→quota(retryable), constraint(19)→typed conflicts; context errors pass through unwrapped (errors.go, classifyStoreError sqlite.go:1088-1111).

## 6. Trust boundaries

- Durable rows re-read as input: snapshots/events/evidence decode persisted JSON and timestamps strictly (malformed → CodeCorrupt surfaced to callers, sqlite.go:840,846,965); structural legality enforced by schema CHECKs plus post-load Snapshot.Validate. Anyone able to write the db file can rewrite gate inputs; controls are filesystem privacy (0700/0600, symlink rejection) + validation, not cryptographic integrity.
- Agent-derived event payloads pass TWO gates before storage: producer-side filtering in app (`runtimeEventDraft` run_control.go:417-545 — sensitive-key denylist secret/token/password/authorization/cookie/api_key/apikey/credential/auth, bounded values, one-level flattening, tool observation redaction replacing secret-shaped strings) and the storage-side sanitizer (`sanitizeEventDraft` sanitize.go:26-61 — allowlist of ~40 product field names, sensitive-fragment denylist secret/token/credential/password/prompt/payload/stdout/stderr/path/command, absolute/drive-letter paths and bearer/sk-/ghp_/github_pat_/private-key markers rejected, NUL/CR/LF stripped, oversize drafts replaced wholesale by a warning stub). Dropped detail becomes Omission counts, never silence.
- Structured logs apply the same sanitizer families locally (local_log.go:69-97: sensitive keys dropped, unsafe values "[omitted]", bounds enforced).
- Reconciliation evidence is deliberately reduced at WRITE time to a class string; the reader re-allowlists to two known values with "omitted" fallback (lifecycle.go:556-565).
- Pagination cursors are opaque bounded base64 JSON with canonical-ID and timestamp revalidation (lifecycle.go:278-291).
- Process identity from /proc or sysctl is treated as exact-birth proof only when complete; partial data classifies uncertain rather than dead (interfaces.go:17-20 contract comment).
- The local workspace is the trust domain: any local process with filesystem access to `.ultraplan/` can accept/claim/cancel/terminalize runs; there is no additional authorization layer between `run cancel` and the database.

## 7. External effects & lifecycle semantics

Effects confined to the workspace `.ultraplan/` tree and its own projections: row inserts/updates/deletes in one SQLite db (WAL sidecars), chmod enforcement, append-only log, migration lock file (other surface), best-effort wal_checkpoint(PASSIVE)+incremental_vacuum after Compact (retention.go:151-152). No network, no signals to foreign processes (probes are read-only), no notifier wired.

Cancellation semantics: user/browser/TUI cancel persists `requested` (idempotent; changed=false on repeats or post-terminal); each owner control loop observes it within ≤1 tick, acknowledges (fenced), then cancels its own context; work drains through product-owned paths; terminal arbitration afterwards decides cancelled-vs-completed with single-winner guarantee. Shutdown: server drain writes leaseless cleanup-uncertain markers elsewhere; runcontrol terminals ride detached 30 s contexts so shutdown cannot prevent terminal commit (shutdown-ordering-chain seam).

Restart/crash semantics: abrupt owner death leaves running rows with expiring leases; startup Reconcile (every process open) plus periodic reconciles convert them to interrupted/cleanup_uncertain using birth-identity proof; unclaimed stale acceptances become interrupted after 45 s grace; repeated reconciliation is idempotent (process_integration_test.go:229-232). Restarted work is a NEW run (claim-once rule), correlated via Correlation.ProductRunID/ParentRun context, never adopted.

Retry/error semantics: busy/unavailable classified retryable; app spine retries appends ≤5 s and terminal proposals indefinitely-with-yields; quota failures stop acceptance/appends but reserve recovery-type writes; permission loss and closed pools produce typed failures with verified no-state-change (fault_test.go:87-129); SQLITE_FULL mid-append leaves last committed sequence intact (fault_test.go:12-50). Observation failures never mutate durable state (follow returns nil on ctx.Done; SSE handlers just stop streaming).

## 9. Contracts (CURRENT-CONTRACT evidence)

From ultraplan-workspace projects/ultraplan-go/docs/TRD.md §18C Phase 6 (~L2185-2212): durable envelope MUST include workspace-scoped run ID, target correlation, lifecycle timestamps, attempt/agentwrap/process correlations, owner identity + renewable lease + heartbeat + fencing value + safe process-birth identity, latest sequence + retention boundary, cancellation request/acknowledgement facts, ONE immutable arbitrated terminal result or explicit cleanup uncertainty. ## 11. Explicit unknowns / open questions (for later reviewers)

1. Event types `accepted`/`claimed` are schema-valid and tombstone-compaction targets but NO production or test path ever writes them; intent (reserved vs vestigial) undocumented — affects anyone reconstructing history from events alone.
2. `operation_aliases.expires_at/recovery_code/recovery_guidance` are never written or read anywhere; alias rows live exactly as long as their run (CASCADE). Whether expiry/recovery was deferred deliberately is unstated.
3. Claim-once semantics: because current_attempt_id is never cleared, a run can never be re-claimed after its owner dies — recovery is always a NEW run. No doc statement found making this permanence explicit.
4. Pragma verification covers four of six DSN settings; `_txlock=immediate` and `_defensive=1` are set but never read back (map-02 SA-1). Correctness of the MAX+1 allocation strategy depends on immediate transactions being effective for every connection.
5. Reconcile spends its batch budget on unclaimed runs first; under a large ownerless backlog the expired-owner scan gets only the remainder — starvation shape unstated.
6. recordReconciliation errors are ignored at both call sites (`_ =`), so decisions can be applied without durable evidence rows.
7. The reconciler terminalizes using the dead attempt's own fence; safety rests on the claim-once invariant (#3) — if ownership were ever transferable, this fence reuse would need revisit.
8. Hard-quota heartbeat refusal forces lease expiry as the shutdown signal for healthy owners; interplay with long-running product operations that ignore context until the next tick (≤1 s + operation duration) is timing-dependent.
9. `cancellation_state='uncertain'` is readable/countable but unreachable through any writer; who would set it and when is unspecified.
10. storageBytes counts every `run-control.db*` regular file (including .migrate.lock and backups) toward quota — intentional? undocumented.
11. compactRunJournal runs synchronously inside every Append transaction once limits are exceeded (latency coupling); a run saturated exclusively with non-removable event types makes ALL further appends fail permanently with CodeQuota until manual intervention — recovery story unstated.
12. Windows has no probe implementation (generic fallback reports uncertainty); platform support matrix implicit (linux-first, darwin variant present).
13. List issues one Snapshot query per row (N+1 within page limit ≤200); performance envelope for large workspaces undocumented.
14. `run follow`/SSE/hub replay loops duplicate cadence constants independently (observation-replay-parity seam); parity relies on copy-paste, unpinned by any shared test.
