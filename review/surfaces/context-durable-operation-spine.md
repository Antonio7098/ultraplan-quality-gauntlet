# Context Pack: `durable-operation-spine` — App durable operation spine

Target: ultraplan-go @ 50d6f0d25ff273f4cb956f11e6030376108110bc (working tree clean except untracked `.ultraplan/`).
Planning context: ultraplan-workspace @ ab12dc38059c9bf485f9aced9075bcd7d924cac5.
Domain: durability-core. Risk: critical. Descriptive only — no defect judgments.

## 1. Purpose

`internal/app` owns the single accept-before-execute chokepoint shared by CLI, TUI, and web: before any runtime-backed work starts, the operation is durably accepted and claimed in `.ultraplan/run-control.db`, and every observable event is committed to that store before it is delivered to any live consumer. Two run tiers exist: OUTER "operation" runs (`Target.Kind="operation"`, one per user-visible operation, managed by `durableOperationManager`) and INNER "runtime" runs (one per agentwrap/OpenCode `StartRun`, managed by `controlledRuntime`), correlated via `Correlation.ProductRunID = ParentRun(ctx)` — the outer context carries its RunID via `runcontrol.WithParentRun` (runcontrol/context.go:7-25). The spine also mints the QA writer-token handoff that lets sprint code fence its private state writes on the outer run's lease. Storage mechanics (accept/claim/append/heartbeat/terminal/reconcile SQL) belong to surface `run-journal-fencing`; this pack covers the app-layer behavior built on top.

## 2. Entrypoints and control flow

### 2.1 Process wiring (`run_control.go:23-95`)

### 2.2 Outer accept — `durableOperationManager.AcceptOperation` (durable_operations.go:97-138)
Input: `Confirmation` (normally produced by `PrepareOperation`, operations.go:211-359) + caller-supplied digest string. Sequence: build `Target{Kind:"operation", Operation=string(req.Kind), Project/Sprint/Study/Stage/Task}` → `repository.Accept(Acceptance{ProductStatus:"prepared", OperationAlias:digest, ConfirmationDigest:digest})` (:103-105). On `ErrConflict` WITH non-empty digest only: resolve alias → return `{RunID, Context: caller ctx unchanged, Existing:true, Lifecycle}` (:106-112) — no claim, no fence, no ownership. Any other Accept error fails closed (:113-115). Then `Claim{Lease: OwnerLeaseDuration=15s}` (:116-119), fence assembled from attempt (:120), first `lifecycle=running` append via `appendRunEventWithRetry`; if THAT fails, proposes `TerminalPersistenceLost` ("operation start persistence failed") on a detached 30 s context using the just-minted fence BEFORE returning the error (:121-129). Success path: `operationCtx = WithCancel(WithParentRun(ctx, RunID))` plus a context value `durableOperationOwnership{repository, fence}` (:130-131); ownership stored in per-instance map `m.owned[RunID]` (:132-135); control goroutine spawned (:136); returns `{RunID, Context: operationCtx, Lifecycle:"running"}`.

### 2.3 QA writer-token handoff (`qaOwnershipFromContext` :140-156)
Extracts `durableOperationOwnership` from ctx; builds `sprint.QAWriterToken{RunID, OperationalAttemptID, FencingGeneration}` (sprint/qa_types.go:179-191) plus a fence closure: full struct equality against the minted token else `ErrStaleFence` (:147-149); on match performs `repository.Heartbeat(context.WithTimeout(context.WithoutCancel(ctx), 30s), fence, 15s lease)` (:150-153) — heartbeating survives outer-context cancellation for bounded post-run writes. Consumers: `durableCLICommand.QAWriterToken()` (:64-69) used by `sprint qa run/resume` (sprint_commands.go:419-442: token+fence → `WithQAWriterFence(fence)` → `RunQA(durable.Context(), ...)`); and `sharedOperationRunner` OperationQAStart/QAResume reads the SAME context value from the accepted operation ctx (operation_runner.go:114-130). Sprint side: `checkWriter` requires a configured fence before every QA publish (sprint/qa_state.go:453-465); without an installed fence sprint falls back to comparing against `req.WriterToken` (sprint/qa.go:260-267).

### 2.4 Event recording + coalescing (`RecordOperationEvent` :158-221)
Adapter emit callbacks call this with `context.Background()`. Unknown RunID → `(false, ErrNotFound)` (:162-164). Per-operation `eventMu` serializes: event type = progress, or warning when `State==OperationFailed` (:167-170); dedup key = concatenation of type/stage/task/phase-state/summary/event-type/kind/tool/reason/detail (:171); identical progress within `ProgressCoalesceWindow`=250 ms (measured against wall-clock `time.Now().UTC()`) increments an in-memory omission counter instead of appending (:174-181, returns `(false,nil)` so adapters ALSO suppress local display). Non-coalesced events build payload {state,type,count "done/total"} plus optional phase_state/summary/tool_*/provider/model/harness keys when non-empty (:182-195); pending coalesced count flushes into the draft's Omission metadata (:196-207); append via `appendRunEventWithRetry`; append error calls `owned.cancel()` and returns the error (:208-216); progress bookkeeping updated only after commit (:217-219).

### 2.5 Manager control goroutine (`controlOperation` :223-264)
1 s ticker (`OwnerTickInterval`, model.go:514): Snapshot poll (:235) — error ⇒ cancel+exit silently (:236-239); `CancellationRequested` ⇒ fenced `AcknowledgeCancellation` then cancel (:240-247); heartbeat every ≥5 s (`HeartbeatInterval`) (:248-254); `Reconcile` every ≥10 s (`ReconciliationInterval`) (:255-261). Any of these errors cancels and exits WITHOUT surfacing or persisting a diagnostic. Exit conditions: ctx done, `owned.stop` closed, or first tick error. `FinishOperation` joins via `owned.done`.

### 2.6 Finish + terminal mapping (`FinishOperation` :266-300)
Pops ownership under mutex (unknown id ⇒ nil, no-op success :267-273). Under `eventMu`: flush trailing coalesced omissions as an omission event; a flush failure becomes `runErr` only when no other error exists (:274-282). Then close(stop) → wait done → owned.cancel() (:283-285). Outcome mapping order (:286-297): `errors.Is(runErr, DeadlineExceeded)` → timed_out; `errors.Is(runErr, Canceled)` OR `state==cancelled` → cancelled; other `runErr != nil` OR `state==failed` → failed; `state==partial` → interrupted; default succeeded. Terminal proposed with retry on detached-or-bounded caller ctx (:298-299).

## 4. Authoritative state

- Durable authority is `.ultraplan/run-control.db` (schema/ownership: surface `run-journal-fencing`). This surface WRITES: outer operation rows (Target.Kind="operation", ProductStatus "prepared"), claims with the single process owner, operation-scope events (progress/warning/lifecycle/omission/terminal), aliases named by adapter digest, terminal proposals. It READS: Snapshots (cancellation state, liveness) every 1 s per active run tier.
- In-memory, per-manager-instance: `m.owned[RunID]` {fence, cancel, stop/done channels, eventMu, coalescing state} (durable_operations.go:14-32); per-controlledRuntime closure state (eventMu, persistenceErr, coalescing state) (run_control.go:189-203).
- Process-wide: `runControlState` repositories/loggers/policies per workspace root + one Owner (run_control.go:23-30); managers created per command (CLI), per TUI session, or per serve process (serve_commands.go:81).
- Derived product state written THROUGH fences by sprint (QA state files) belongs to surface `sprint-qa-investigation`; the spine only guarantees heartbeat-backed fencing.

## 5. Invariants (as implemented)

- Accept-before-execute: no child runtime work begins until Accept+Claim(+first append for operations; Accept+Claim for runtime runs) succeed; acceptance-persistence failure prevents base.StartRun entirely (test-pinned, §10).
- Persistence-gated delivery: display/downstream callbacks fire only after the corresponding Append commits, in both spine variants (run_control.go:246-248; web publishAppEvent; TUI emit gating).
- One claim per run lifetime, one terminal winner, monotonic sequences: inherited from runcontrol CAS/fencing (dependency surface); this surface always operates through freshly minted per-attempt fences and never mutates rows directly.
- Fail-closed on persistence loss: mid-run append/heartbeat/poll/reconcile failure cancels the run context (work drains through cancellation) and ends in a `persistence_lost` terminal proposed on a detached context; start-time append failure terminalizes before returning.
- Coalescing never loses counts: collapsed duplicates accumulate into Omission {reason, count, first/last} carried by the next committed event or flushed at finish; committed=false also suppresses duplicate local display.
- Cancellation path: external request persisted (ownerless) → observed within ≤1 s tick → fenced AcknowledgeCancellation → local context cancel → product drains → terminal arbitration decides cancelled-vs-completed with single-winner guarantee.
- Detached-terminal discipline: every finish/terminal/QA-heartbeat write uses a fresh ≤30 s background context (`context.Background()`/`WithoutCancel`), so shutdown or run-context cancellation cannot prevent terminal commit; append retries are strictly 5 s-bounded.
- Single process owner: all claims of one process share Owner.ID; fencing generations distinguish attempts.
- Boundedness at the boundary: target fields ≤512 B, payload values ≤32 KiB, payload ≤30 entries, keys ≤128 B, control bytes stripped before storage validation sees them.
- Structural pinning: runtime-backed CLI entries must cross `beginDurableCLICommand` (inventory test, §10); TUI/web must go through `DurableOperationManager.AcceptOperation` (capability interface assertion pattern).

## 6. Trust boundaries

- Transport → server: `ExpectedFingerprint` stripped and recomputed server-side; stale fingerprint rejected before runner dispatch (operations.go:215, :376-386). Confirmation tokens consumed once server-side (web preparation store); dedup keys derived server-side from session+token (security.go:448-451). The digest persisted into `operation_aliases`/`confirmation_digest` is always the server-computed hash, never raw transport data.
- Runtime/provider events → durable store: untrusted maps pass the app-side pipeline (denylist keys, redaction markers, bounds, flattening caps, §2.9) AND the runcontrol storage sanitizer; dropped detail becomes Omission metadata, never silence.
- Context-carried capability: `durableOperationOwnership` (repository + fence) travels in context values; QA token equality (struct compare incl. generation) is the only check that a caller presenting a token owns the fence; possession of the ctx (or token) IS the authority.
- Workspace-local trust domain: any local process may open the same db and accept/claim/cancel; no authorization layer between adapters and repository (inherited posture from dependency surface).
- Child-process boundary: `run_control_run_id` metadata injection clones the caller's metadata map before mutation (run_control.go:186-187); prompt content itself is never persisted here (test-pinned "never persisted").

## 7. External effects & cancellation/retry/restart/error semantics

Effects: runcontrol db rows/WAL via shared pool; child runtime execution (network sessions, provider APIs — owned by platform/runtime surfaces); sprint/study/QA workspace file mutations triggered by product code running INSIDE accepted contexts; stdout/stderr presentation. No direct filesystem writes by this layer beyond what repository/logger do.

Acceptance failure ⇒ operation never exists beyond its accepted row (if any); CLI exits ExitRuntime; web handler surfaces error (unless degraded mode). Claim failure after successful Accept leaves an accepted-unclaimed row for reconciliation (grace 45 s — dependency surface). Start-append failure ⇒ persistence_lost terminal, start aborts. Mid-run persistence failure ⇒ runCtx cancel → base runtime observes cancellation → persistence_lost terminal; error joined into returned error (runtime tier) or implicit via context (operation tier). Heartbeat/poll/reconcile failure ⇒ same cancel path (manager variant silent; runtime variant recorded). Retry posture: appends ≤5 s on Unavailable/Busy; terminals effectively until 30 s ctx expiry. Restart/crash: abandoned outer runs keep leases expiring at 15 s; reconciliation (startup + periodic, dependency surface) terminalizes them interrupted/uncertain using birth identity; restarted work is a NEW run correlated by ParentRun/ProductRunID, never adopted. Shutdown: process Close() closes pools last; all terminal proposals ride detached contexts; web drain records cleanup-uncertain via separate capability (web_usecases.go:540-561 — adjacent seam).

## 11. Explicit unknowns / open questions (for later reviewers)

1. Ownership scoping asymmetry: alias dedup is repository-wide but `m.owned` is per-manager-instance; a different manager (or process) cannot finish/record for a run it did not accept (nil-op success / ErrNotFound). Cross-instance finishing relies solely on lease expiry + reconciliation.
2. Manager-tier tick failures (snapshot/ack/heartbeat/reconcile) cancel silently — no surfaced diagnostic, no persisted warning event, in contrast to the runtime tier's setPersistenceErr recording.
3. Two independent coalescing implementations with different key spaces (full tuple vs payload-hash) and different clocks (wall now vs event.Time fallback now); parity between them is unpinned.
4. `payloadHash` is plain concatenated string comparison despite the name; excludes exactly three identity keys.
5. `RecordOperationEvent`/finish-flush hold the per-operation mutex across Append including the 5 s retry window — serialization point per operation.
6. TUI emit swallows RecordOperationEvent errors (no display change, no local signal); internal owned.cancel still fires.
7. Alias-conflict Existing results carry the CALLER's ctx unchanged, no fence, possibly-terminal lifecycle; each adapter projects it differently (refresh path vs static card).
8. Start-append failure path terminalizes a run that executed nothing as persistence_lost — intended shape unstated.
9. Web degrade mode (durable capability absent) continues fully in-memory with hub-generated ids and NO persistence gating — designed fallback; which deployments hit it depends on wiring (serve always wires one today).
10. `deps.ctx` is process-lifetime; Ctrl-C/signal propagation into CLI operation contexts depends on cfg.Context wiring outside this surface.
11. Inventory pinning works by literal string-counting two specific files; new runtime-backed entry points elsewhere would not trip it unless added to the table.
12. `boundedSafe`/`boundedPayloadValue` truncate raw bytes (may split multi-byte runes) before storage-side validation.
13. QA fence equality is whole-struct comparison; token reuse across attempts fails only via generation mismatch — dependency on runcontrol's monotonic generation guarantee.
14. Abandoned-but-unfinshed outer operations (adapter crash between accept and finish) leave running rows until 15 s lease + grace reconciliation; no app-level sweeper exists.
15. `RecordOperationCleanupUncertain`/`ReconcileOperations` (web shutdown drain) write product-owned cleanup markers, not runcontrol rows — relationship to outer run terminals is defined only by convention.
