## 1. Purpose

Read-only, bounded adversarial QA over one sprint's changed paths. The surface decomposes execute-evidence changed paths into a byte-stable shard map, runs fenced read-only LLM "investigators" per shard under hard budgets (turns, retries, timeouts, output bytes), accepts only strictly decoded theory drafts with closed outcome enums, deterministically synthesizes outcomes/dedup/contradictions/follow-ups, and persists everything in a private `verification/` tree whose flow-state pointer is always written last. QA annotates; it never changes the Conformance Review verdict, promotes issues, or repairs code (cli-reference.md:346-361; ARCHITECTURE.md verification-boundary section).

## 2. Entrypoints and control flow

- **status**: `QAStatus` — read-only projection of the pointer and its referenced records.
- **recover**: `RecoverQA(ctx)` under the full mutation lease.
- **cancel**: builds `dashboardUseCases` and calls `CancelQA` — run-control only; no sprint mutation lease is taken.
- **run/resume**: `beginDurableCLICommand(OperationQAStart/QAResume)` (accept-before-execute), `durable.QAWriterToken()` mints token+fence from the accepted operation context (durable_operations.go:64-69,140-156), then `sprintRuntimeService(...).WithQAWriterFence(fence).RunQA(durable.Context(), …)`. Afterwards `QAStatus` is re-read for the result projection; `finishDurableCLICommand` proposes the run terminal. All actions append the review-status projection via `withQAConformanceReview` (sprint_usecases.go:747-758, `WithoutStatusWrites`) and render through `renderSprintQA`/JSON envelope with `mapQACommandError` exit mapping (sprint_commands.go:662-679: canceled/deadline→8, runtime/persistence→6, other QA categories→5).

### 2.3 QAMap → BuildQAMap (qa_map.go:43-137, 139-277)
Pure map construction: settings validation → `PrepareReview(ReviewRequest{})` must return zero findings → `LoadFlowState` gate: `flow.Review` non-nil, non-stale, fingerprint set, Status ∈ {Completed, Blocked} (terminal) → changed paths = `normalizeQAStrings(manifest.ChangedPaths)`, rejecting empty or single "(…)" placeholders ("execute evidence does not enumerate changed paths") → `targetIdentity(manifest.Target)` as implementation fingerprint → input refs from manifest input hashes (missing ⇒ stale) plus review.md digest when recorded → governed/policy/check-catalog fingerprints are sha256 over canonical JSON (fingerprintQAValue) → adjacent-context pairing `<file>.go`↔`<file>_test.go` by os.Stat → expectation refs from coverage IDs else `["governed-plan"]` → git identity (HEAD, hashed cached diff, hashed status --short) → approved-check catalog. `BuildQAMap` groups paths by `qaBehaviorGroup` (extension allowlist .go/.md/.html/.js/.css/.yml/.yaml/.json/.sh/.sql; keys internal/<pkg>, cmd/<pkg>, root/<ext>, or top dir), sorts groups, chunks per ChangedPathsPerShard, pre-blocks unclassified paths (Phase blocked + blocker, no silent omission), adds one boundary shard when >1 primary (overlap = first changed path of each primary, capped at ContextPathsPerShard), enforces PrimaryShards/TotalShards/PendingEntries budgets, sorts shards by content-derived ID, and enforces exactly-one-primary-owner per changed path in `ValidateQAMap`. `NormalizedQAMapBytes` (MarshalIndent+\n) is the byte-stable form.

### 2.4 RunQA (qa.go:237-360)
Ordering: require runtime + valid token + valid settings → wrap progress with `boundedQAProgress` (RecentProgress cap, mutex) → `acquireMutationContext` (in-process sync.Map + pidfile lease held for the whole run) → writer-fence fallback comparator if no real fence installed (qa.go:258-267) → store with fence → `PruneAttempts("")` retention sweep → `VerificationBytes()` ≤ StateBytes else budget-exhausted → `QAMap` rebuild → second `PrepareReview` (findings ⇒ StaleInput) → `LoadFlowState` → `prepareQAAttempt`:
- **Resume** (req.Resume ∧ prior.CurrentAttemptID == current SemanticAttemptID ∧ prior.Map != nil): retained Completed/Blocked shards reloaded from disk; run correlation reset to the NEW token (Claimed), phase queued, blocker/cancellation cleared, published.
- Otherwise fresh: phase mapped, Map+Shards+State published together, state reloaded, prune protecting the current attempt. A resume whose prior attempt ID mismatches silently falls through to this fresh path.
Then phase running published (state only) → `runQAShardBatch` #1 → on error `terminalQAState`+publish+return; else synthesizing publish → pure `SynthesizeQA(map, shards)` → if follow-up shards proposed: append them (TotalShards grows), run batch #2, re-synthesize → `hydrateQASynthesisFollowUps` requires every follow-up to have reached retained terminal Completed/Blocked → final publish (all Shards + Synthesis + completed State) → reload state → emit complete.

### 2.5 Shard execution (qa.go:428-666)
Batch skips already-terminal shards unless FocusShard selects one (unknown/terminal focus ⇒ InvalidState). Workers = min(ConcurrentInvestigators, pending); jobs/results channels; a publication failure closes `abortResults` and cancels the batch context while draining results; per-result shard phase mapping: Canceled→cancelled, DeadlineExceeded→interrupted, other errors→blocked (+blocker); state republished after EACH terminal shard. `runOneQAShardSafely` recovers panics into RuntimeUnavailable blockers. `runOneQAShard`: `validateCurrentQAMap` (installed qaMapFence, else full deterministic map rebuild comparing map IDs) → investigator request built from `RenderQAInvestigatorPrompt` (packet JSON embedded; PromptBytes cap) with Sandbox=read_only, Permissions=restricted, RequireCaps=[permissions], tool policy default deny {read,list,search,glob allow}, PathRules allow-listing contained changed+context paths, Timeout=ShardTimeout, metadata operation/task/operational_attempt → retry loop ≤ RuntimeRetries+1: targetIdentity before-run must equal map fingerprint (else StaleInput); StartRun; identity after-run drift ⇒ PermissionDenied; map revalidated (governed-input drift ⇒ StaleInput); result.Permissions must be restricted/deny/0-unsupported else PermissionDenied fail-closed; success path enforces Turns ≤ IterationsPerAttempt else BudgetExhausted; failure classification (`classifyQARuntimeFailure`): canceled/deadline return immediately; result.Error.Category ∈ {validation,invalid_input,permission_denied,configuration,unsupported} non-retryable; unknown categories retryable until the bound. Then `decodeQAInvestigatorOutput`: TerminalOutput or last event payload["content"], size ∈ (0, ShardOutputBytes], strict single JSON object, DisallowUnknownFields, schema_version==1 → output-count budgets vs TheoriesPerShard/ContextExpansions/CommandsPerAttempt → context requests: self-approval (Approved=true) rejected PermissionDenied, path count ≤ PathsPerExpansion, each path validateQAPath (requests are recorded only) → checks: catalog recomputed live via `ApprovedQAChecks`; each requested ref must match ID+Fingerprint exactly else PermissionDenied; `RunApprovedQACheck` re-verifies map ownership, descriptor validity, captures targetIdentity before/after (drift ⇒ PermissionDenied), runs argv via `processRunner.Run` (DirectRunner) with env copied only for allowlisted names present in the parent environment, records digests/exit/duration/truncation, treats exit≠0 as RuntimeUnavailable abort → theories get product-assigned IDs (`NewQATheoryID` over normalized claim/basis/surface/refs), fingerprint = pre-attempt implementation identity, full attempt history, `ValidateQATheory` (closed outcome enum, all falsifiability fields required, 64-hex fingerprint); zero theories ⇒ InvalidState; final map revalidation; theories sorted by ID; shard Completed.

### 2.6 Approved-check policy (qa_prompt.go:59-134, 243-285)
Catalog today is a single descriptor `go-format-diff` (gofmt -d <changed .go paths>) when any changed path ends .go; cwd pinned to target root; timeout/output limits from budgets. `validateQACheckDescriptor` bans interpreters/shells/git (lowercased basename blocklist), shell/redirection metacharacters in args, `-w`/`--write*` flags, arg paths that are absolute or escape the target, and env names outside {LANG, LC_ALL, TZ}. Descriptor fingerprint covers all fields except the fingerprint itself.

### 2.7 Synthesis (qa_synthesis.go)
Pure over validated inputs; rejects shards from another semantic attempt. Sort-normalizes shards/theories/challenges; challenge count ≤ FollowUpShards, each must reference known theory IDs and carry the map ID. Equivalence key = lower(join(claim, verification_surface, sorted expectation refs)) drives dedup (first ID retains the rest) and contradiction detection (confirmed ∧ refuted in one group). Interactions pair cross-shard theories or pairs sharing risk tags. Follow-up candidates = cross_shard/inconclusive theories capped at FollowUpShards; each becomes a follow_up shard with parent-theory link and deterministic ID. Blockers collected and sorted; NextAction ladder follow-ups > blockers > inspect. `ValidateQASynthesis` re-checks identities, budgets, references.

### 2.8 Status/recover (qa.go:55-205)
`QAStatus` loads the pointer then referenced records strictly; missing state.json yields a Missing-phase snapshot (nil error); synthesis loads under map budgets (or Maximum); planned + follow-up shards merged sorted; never writes. `RecoverQA` holds the mutation lease; recomputes the expected flow summary from current state.json bytes digest; queued/running/synthesizing ⇒ Interrupted (Conflict blocker "prior process stopped…"); mapped ⇒ Interrupted with resume hint; ANY current-map error or semantic-attempt mismatch ⇒ Stale + not-current; unchanged states return untouched; changes go through `SaveRecoveredState` (state write + flow pointer only) then optional prune. `SaveRecoveredState` refuses active phases (qa_state.go:429-434). Boot-time reconcile additionally converts queued/running/synthesizing to Interrupted via SaveRecoveredState (locks.go:76-97).

## 5. Invariants (as implemented)

- Closed enums everywhere: 11 phase statuses, 7 theory outcomes, 8 error categories (pinned by test).
- Deterministic identity: identical semantic inputs reproduce attempt/map/shard/theory/challenge/synthesis IDs byte-for-byte; any fingerprint or changed-path change yields new IDs.
- Byte-stable maps and syntheses (MarshalIndent canonical ordering; sort-before-emit everywhere).
- Budgets are lower-only: workspace/env may reduce, never exceed, shipped maxima; both config loader and `validateQABudgets` enforce positivity and maxima.
- Publication order: writer-fence check first (fail-closed when no fence configured in the store, qa_state.go:453-464), then map (immutable) → shards → synthesis → state LAST → flow pointer last-of-all via SaveFlowState; every record temp+fsync+rename with 0700 dirs (chmod walk up to `verification`) and 0600 files; load requires regular file with perm exactly 0600, ≤128 MiB, schema_version==1 (0 ⇒ InvalidState, other ≠1 ⇒ UnknownSchema), DisallowUnknownFields, single JSON value; referenced artifacts re-hashed against recorded digests on load.
- Read-only enforcement is verified, not assumed: post-run permission summary must be restricted/default-deny/zero-unsupported; self-approved context expansions rejected; check requests must reference catalog-owned descriptors by ID+fingerprint; target identity captured before/after every investigator attempt and approved check.
- Exactly-one primary owner per changed path; boundary/follow-up shards never own primary coverage.
- Recovery can only publish non-active phases and only touches state.json + flow pointer.
- Progress emission is capped (RecentProgress) and mutex-guarded.

## 6. Trust boundaries

- **Investigator structured output** (LLM-controlled): strict decode, size caps, closed enums, mandatory falsifiability fields, product-assigned IDs/fingerprints/timestamps; outcome text never mutates review verdicts, issues, or code.
- **Check execution**: catalog is recomputed server-side each run; descriptors cannot name interpreters, shells, git, write modes, escaping paths, or arbitrary env; cwd pinned to the target; post-run drift detection; child output re-enters only as digests/summaries.
- **Changed paths** derive from execute evidence via the review manifest and pass `validateQAPath` (no absolute/`..`/NUL/CR/LF) before becoming prompt content, path rules, or gofmt args.
- **flow-state Review record** is trusted gate input for mapping (terminal + non-stale + fingerprinted); mitigations live upstream in review freshness/digest machinery, not here.
- **Writer tokens**: minted only inside the durable acceptance boundary from `runcontrol.Fence{RunID, AttemptID, FencingGeneration}`; compared field-for-field on every Publish; each successful check heartbeats the outer lease (WithoutCancel+30s), so state writes are coupled to lease liveness; ErrStaleFence surfaces as Conflict "writer token is stale".
- **Private storage**: 0700/0600, symlink rejection on every path component and during byte measurement; digest-pinned internal references defeat tampered record swapping.
- **Presentation**: progress messages pass config.RedactValue at CLI rendering (sprint_commands.go:440); projections use displaySafe.

## 7. External effects & lifecycle semantics

Effects: writes confined to the verification tree + flow-state QA pointer (+DB mirror via SaveFlowState when authoritative); spawns OpenCode investigators (isolated per-owner SQLite stores under the runtime surface) and short-lived gofmt subprocesses; appends run-control events through the spine; prunes old attempt dirs (RemoveAll).
Timeouts: RunTimeout bounds the whole run (context derived from the leased context); ShardTimeout rides the runtime request; CommandTimeout bounds checks; CleanupTimeout is the process-runner cleanup grace. Cancellation: `qa cancel --run` (or browser/TUI cancel) → ownership-prechecked CancelRun request → spine control loop acknowledges within OwnerTickInterval and cancels the operation context → in-flight shards observe ctx cancellation, persist cancelled/interrupted phases without retry, and RunQA publishes a cancelled terminal state; the fence heartbeat uses WithoutCancel so terminal publication can outlive the canceled parent. Crash/restart: dead owners leave queued/running/synthesizing residue; `ReconcileInterruptedMutation` (boot) or `RecoverQA` converts it to explicit Interrupted evidence; resume always creates a NEW durable owner and never adopts prior sessions/runtimes; retained terminal shards are reused only while the semantic attempt ID still matches the freshly computed map. Retry taxonomy: runtime-level retries per shard (category-whitelist classified), no automatic cross-shard retry, resume/recover as the operator-level retry. Exit classes: usage 2 / config 3 / validation·stale·policy 5 / runtime·persistence 6 / canceled·deadline 8 (docs/cli-reference.md:363).

## 11. Explicit unknowns / open questions (for later reviewers)

1. Challenger integration: QAChallengerRequest/BuildQAChallenge/SynthesizeQAWithChallenges are implemented and tested, but RunQA always calls SynthesizeQA (challenges=nil). Whether challenger invocation is intentionally deferred (TRD gates later phases) or an unfinished wire-up is not stated in-tree.
2. qaWorkspaceInputRef (qa_map.go:403) has no callers anywhere in the repo; intent undocumented.
3. Investigator context requests are validated and persisted but never expanded/executed by this surface — whether expansion belongs to a later phase is unstated here.
4. Resume with a mismatched prior attempt ID silently starts a fresh attempt rather than erroring; cli-reference says resume continues "current valid shards" — mismatch semantics are implicit.
5. RecoverQA marks the state Stale on ANY QAMap error, including transient read/preparation failures, conflating staleness with unavailability in the persisted phase.
6. Publish validates synthesis against MaximumQABudgets while QAStatus validates against map budgets when present — two different budget lenses on one record.
7. Every Publish performs a run-control Heartbeat (30s WithoutCancel) — behavior when the lease is already lost or cancellation was just acknowledged (heartbeat error ⇒ Publish fails ⇒ different error path) deserves reviewer attention.
8. privateAtomicWrite chmods EVERY existing ancestor up to `verification` to 0700 on each write, mutating pre-existing directory modes on the shared sprint path.
9. runQAShardBatch processes results sequentially while workers continue; after a publication failure late results are drained but not published, and shards completing after abort have no persisted record until a later full publish (which early-return paths skip).
10. QA state itself has no heartbeat/expiry analogue to review's ActiveAttempt mechanism; liveness rests entirely on durable leases plus explicit recover/reconcile.
11. Boundary-shard overlap uses the first changed path of each primary shard as representative rather than computed overlap semantics; "boundary" is therefore a naming convention.
12. POSIX assumptions: permission model (chmod walk, 0600 exact-match load check) and gofmt availability are environment-dependent; no build-tag variants exist for the QA store.
