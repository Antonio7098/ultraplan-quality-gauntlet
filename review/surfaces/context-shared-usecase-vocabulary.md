# Context Pack: `shared-usecase-vocabulary` — Cross-interface operation vocabulary and parity

Target: ultraplan-go @ 8eef70f4903b25580719960009a170945bdad9ad (frozen).

Domain: operator-interfaces. Risk: high. Descriptive only — no defect judgments.

## 1. Purpose

The convergence fabric behind CLI, TUI, and web: one typed operation vocabulary (`OperationKind`, 27 constants), one prepare→confirm→accept→run pipeline (`PrepareOperation`/`RunOperation` plus the optional `DurableOperationManager`), one shared runtime-backed executor (`sharedOperationRunner`), and one durable landing format (run-control rows whose `Target.Operation` stores the kind string; dedup keys stored in the `operation_aliases` table and `confirmation_digest` column). Three structurally different acceptance-digest regimes (web session+token hash, TUI content hash, CLI empty) feed the same alias column. Cancellation reasons and cancel-time target checks differ per door before converging on `RequestCancellation`. Read-only composition is split: web composes `readOnly=true`, TUI leaves it false. Durable-event replay/polling exists as three structurally similar Go loops plus an SSE/in-memory replay pair.

### 2.6 Acceptance digest regimes (three doors, one alias column)
- **Web**: prepare issues a `preparationStore` record bound to (session, CanonicalRequest, InputFingerprint) with 2-min TTL, ≤128 records, typed replay/expiry/mismatch/stale errors (security.go:368-446). Start re-prepares then consumes the token inside the hub callback; dedup key = sha256(session+"\x00"+confirmationToken) hex (security.go:448-451); `startConfirmed` checks in-memory `h.dedup` first (same-session only; stale mapping deleted), enforces draining/capacity, then calls `AcceptOperation(ctx, prepared, dedupKey)` (operations.go:150-218). Alias hit returns doc {ID=existing run id, State=accepted.Lifecycle, RefreshPath=/runs/<id>} without starting work (:193-198). If the use cases lack the durable capability (`ErrWebUnavailable`) the hub proceeds in-memory only.
- **TUI**: digest = hex(sha256(CanonicalRequest + "\x00" + InputFingerprint)) computed in `beginOperation` when a Confirmation exists and use cases implement the manager (internal/tui/app.go:232-254); Existing renders non-running result "matching durable operation already exists".
- **CLI**: `beginDurableCLICommand` wraps runtime-backed commands (flow, verify, execute, review, smoke, qa start/resume, study start/resume/task-analysis/task-synthesis) with `AcceptOperation(ctx, Confirmation{Request: request}, "")` — empty digest, so no alias row and no dedup (durable_operations.go:49-60; inventory pinned by run_control_inventory_test.go). The wrapper keeps the manager alive for the command and provides Context() and QAWriterToken(); Finish maps ctx.Err()/error → complete/cancelled/failed with 30 s timeout (durable_operations.go:62-91).
- **Landing**: all three converge on `repository.Accept(Acceptance{Target:{Kind:"operation", Operation:string(kind), Project, Sprint, Study, Stage, Task}, ProductStatus:"prepared", OperationAlias:digest, ConfirmationDigest:digest})` (durable_operations.go:97-115). SQLite persists target_kind/operation_kind/project_id/sprint_id/study_id/stage_id/task_id + confirmation_digest on the runs row and inserts an `operation_aliases(alias_id, run_id, alias_kind='operation')` row only when the digest is non-empty; alias conflicts surface as CodeConflict "operation alias already exists"; values bounded by MaxSafeValueBytes, control chars rejected (sqlite.go:402-455). `ResolveOperationAlias` maps alias→Snapshot (:472-484). Accept also enforces soft-quota compaction/refusal (:380-395). After accept: Claim with OwnerLeaseDuration, lifecycle-running event (failure proposes persistence_lost terminal), ownership {repository, fence} into the operation context, control goroutine started (durable_operations.go:116-137).

## 5. Cancellation semantics (per-door divergence)

All doors end in `RequestCancellation(runID, reason)` (lifecycle.go:70-134: reason required non-empty, ≤MaxSafeValueBytes, no control chars; idempotent no-op when terminal or already cancelling; CAS on last_sequence; appends cancellation event; lifecycle→cancelling; owner acknowledges within tick cadence).
Reason vocabularies actually sent:
- Browser hub path: canonicalCancelReason folds arbitrary input to {server_shutdown, timeout, recovery, else user_request} (operations.go:625-632); handlers pass literal "user_request" (operation_handlers.go:207, 390); drain passes "server_shutdown" (:490). Note spelling differs from the CLI/TUI family ("user_request" vs "user_requested").
- Browser durable fallback + TUI: "user_requested" (operation_handlers.go:209, 392; tui/app.go:110, 124).
- CancelQA use case: "read-only QA cancellation requested" (sprint_usecases.go:731), gated by membership check: snapshot Target.Project/Sprint must equal request and Target.Operation ∈ {qa-start, qa-resume}, else "QA run does not belong to the selected sprint" (:716-737).
- CLI `run cancel --reason`: validated against {user_requested, operator_requested, shutdown_requested, quota_exceeded}, default user_requested (run_commands.go:201-216, 394-401).
Target-check divergence: hub cancelOperation checks only session ownership (empty-session callers may cancel any record; used intentionally by drain, operations.go:350); durable fallback/status require Target.Kind=="operation"; CancelQA adds project/sprint/operation membership; TUI cancels ActiveRunID or the open RouteRun ID with no target-kind recheck; CLI run cancel accepts any well-formed run id. Study-cancel is not a RequestCancellation at all: it becomes OperationStudyCancel → SIGINT to the PID recorded by the study lock.

## 6. Replay / polling logic (parallel implementations)

Same durable-replay semantics implemented independently:
1. CLI `run follow`: Events(after,512)+Snapshot loop; exits when terminal ∧ after≥LastSequence; waits 250 ms catching up else 1 s idle (run_commands.go:131-195).
2. Web durable SSE fallback `followDurableOperationEvents`: identical shape (Events(after,512)/Snapshot/terminal check/wait 1 s|250 ms) projecting durable events to stable SSE names (operation_handlers.go:447-514).
3. TUI run-detail refresh: on every load/refresh/1 Hz tick fetches page (limit 200) and, when the route is a run detail, Snapshot then RunEvents(after = OldestRetainedSequence−1, limit 200) (tui/app.go:360-390).
Adjacent but distinct mechanisms sharing the conventions: REST/SSE run events endpoint with cursor_ahead/replay_gap conflicts (Last-Event-ID vs after exclusivity; run_handlers.go:930-990+) and the same OldestRetainedSequence−1 start convention (run_handlers.go:337-338); in-memory hub subscribe replay with recovery_required+snapshot synthesis on gap (operations.go:376-426); browser static/js/sse.js Last-Event-ID reconnect pinned by contract test.

## 7. Trust boundaries

- Same logical action arriving via different doors must produce equivalent durable semantics (assignment framing): kind string, Target fields, and lifecycle writes are shared; identity entering the alias differs by design — web binds to (session, token) [per-browser anti-double-submit], TUI binds to content (canonical+fingerprint), CLI binds to nothing (every invocation its own run).
- Caller-supplied ExpectedFingerprint is stripped twice (prepare entry :215; RunOperation :377-378) and re-issued server-side; stale detection compares fresh fingerprint after re-hash of governed inputs.
- Identifier admission is layered: transport-level validOptionalIdentifier (web), validateOperationScope ([A-Za-z0-9._-] etc.), QA field lockdown enforced at both transport (mapOperationRequest) and app (validateQAOperationRequest) layers.
- Fingerprinting rejects symlinks anywhere in governed inputs and hashes with relative-path separators; missing files skipped (TOCTOU between hashing and execution is inherent to the mechanism).
- Sanitization boundary into durable/display data: displaySafe (app) for findings/errors/projections; payload whitelisting/bounding in RecordOperationEvent (durable_operations.go:182-195) and runtimeEventDraft (run_control.go:417-545, sensitive-key denylist, 30-key cap, bounded values); safeWebText redaction for web projections; safe command/event-name allowlists.
- Cancellation authority: repository validates reason format only; membership/ownership semantics are per-door policy (§5).
- Hub session model: signed cookie session + CSRF for API mutations; empty-session bypass exists for internal drain only.

## 8. External effects & retry/restart/error semantics

Effects per accepted operation: run rows/aliases/events/terminals/cancellation records; product mutations only via sharedOperationRunner services (workspace artifacts, review/smoke/QA trees, git publication inside those surfaces); SIGINT lane for study-cancel; cleanup-uncertainty records on web shutdown deadline overrun. Retry: web door has explicit idempotent replay (same session+token returns original operation; local dedup map + durable alias); TUI door dedups identical confirmed content via content digest until alias retained; CLI door has none (new run each invocation). Restart/recovery: repository open performs startup reconcile; explicit recovery exposed as vocabulary items (qa-recover; ReconcileOperations over all sprints/studies at serve startup paths); cleanup_uncertain marks unprovable cleanup. Error semantics unified through failedOperation taxonomy (§2.5) for app results and writeOperationError table (status/code/guidance/retryable) for HTTP; TUI renders OperationError blocks from the same taxonomy.

## 12. Explicit unknowns / open questions (for later reviewers)

1. 2. Three digest regimes land in one alias column with different keyspace semantics (content hash vs session+token hash vs absent). Whether any consumer distinguishes ConfirmationDigest from OperationAlias (today written identically) or reasons about cross-door duplicate actions (same action confirmed in TUI and web produces two runs) is unstated in-tree.
3. Alias retention lifetime relative to compaction/tombstone (can ResolveOperationAlias still answer after history pruning?) belongs to the spine surface; unresolved here.
4. Cancellation reason spellings diverge across doors ("user_request" vs "user_requested" vs free-form-but-canonical CLI set vs prose "read-only QA cancellation requested"); whether any consumer filters or displays reasons canonically was not traced beyond run_handlers rendering.
5. `hub.start(session, prepared)` (empty dedupKey, no durable accept fallback path exercised) appears test-only in-tree; production reachability unknown.
6. sharedOperationRunner ignores time.ParseDuration errors for Timeout (operation_runner.go:82-84, 103-105) while PrepareOperation's smoke preview reports EffectiveTimeout/TimeoutSource from the sprint layer; whether invalid caller timeouts silently mean "no override" everywhere is undocumented.

10. Web-only vocabulary extras (legacy kind aliases, underscore normalization, action/dry_run folding) have no counterpart filtering in TUI/CLI; the authoritative minimal kind set is the enum itself.
