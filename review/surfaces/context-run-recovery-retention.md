## 1. Purpose

This surface is the durability and housekeeping half of run control. It owns four mechanisms the journal itself depends on: (1) schema creation/migration with private timestamped backups, integrity verification, and proven-stale migration-lock reclaim (`migration.go`); (2) crash reconciliation that converts expired/unclaimed ownership into conservative terminal states with evidence rows (`lifecycle.go:Reconcile`); (3) retention — inline per-run event compaction during append, plus whole-record compact → tombstone → delete aging and soft/hard quota gates at accept/append/heartbeat (`retention.go`, `sqlite.go` gate sites); and (4) the bounded diagnostic sinks — the private `.ultraplan/run-control.log` (`local_log.go`), the final storage sanitization allowlist (`sanitize.go`), and the operator-facing `run diagnostics --support-export` document (`internal/app/run_commands.go`). The offline restore-from-backup procedure is an exported package function, not a CLI door (docs/recovery.md:236-243).

## 2. Entrypoints and control flow

### 2.1 Open path (migration entry)
`OpenSQLite` (sqlite.go:60-134): `validateWorkspaceRoot` → `preparePrivateDatabase` (154-191: Lstat-rejects symlinked/non-dir `.ultraplan`; creates it 0700; creates `run-control.db` O_EXCL 0600 if absent, rejects symlinks/non-regular; `enforcePrivateMode` chmods then re-stats verifying exact mode) → DSN with fixed pragmas (`_busy_timeout=5000 _foreign_keys=on _journal_mode=WAL _synchronous=FULL _txlock=immediate _defensive=1`) → ping → `verifyPragmas` (207-227: re-reads all four pragmas, mismatch = CodeInvariant) → **`migrateSchema`** → chmod verify → `normalizeRetentionPolicy`. Production callers: `app.runControlState.repository` (app/run_control.go:56, followed by logger open, SetLogger, and startup `Reconcile` whose failure aborts the command) and `storage migrate` (app/storage_commands.go:60, default retention, no startup reconcile).

### 2.2 migrateSchema decision table (migration.go:25-82)
- Read `PRAGMA user_version`. Version > `CurrentSchemaVersion`(1) → ErrUnsupportedSchema, no writes, before any lock.
- Version == 1 (common multi-process path): `verifySchemaRecord` (app_schema row for 'run_control' must exist and equal 1; missing = CodeCorrupt, mismatched = CodeUnsupportedSchema) then `integrityCheck` (`PRAGMA integrity_check`; any row ≠ "ok" = CodeCorrupt). No lock contention by design (comment migration.go:33-35).
- Version < 1: acquire `databasePath + ".migrate.lock"` via `O_CREATE|O_EXCL|O_WRONLY` 0600. On EEXIST: `removeStaleMigrationLock` (140-165) reads the file as JSON `ProcessIdentity`; unparseable or failing `Validate()` → "cannot authorize removal", stays Busy (CodeBusy retryable); probe stored PID natively: ErrProcessNotFound → proven gone, unlink and retry acquire once; other probe error or probe matches expected identity exactly → owner alive/uncertain → Busy; birth-mismatch → PID reuse proven → unlink and retry. After acquiring: probe own identity first (failure = CodeUnavailable + lock removed); write JSON identity + `\n`, fsync, close; release closure unlinks the path.
- Under lock: re-read version (another process may have migrated). If still 0: `hasApplicationSchema` counts any non-`sqlite_%` table/index/trigger; if present → `checkpointWAL` (`PRAGMA wal_checkpoint(TRUNCATE)`; busy ≠ 0 → CodeBusy retryable, abort) then `createMigrationBackup`: stat size ≤ `maxBackupBytes` 512 MiB, name `<db>.bak.<UTC yyyyMMddTHHMMSS.000000000Z>`, `copyPrivateFile` O_EXCL 0600 with io.LimitReader(limit+1) re-check, fsync, remove-on-failure. Then `createInitialSchema` (sqlite.go:344-366): one transaction executing `initialSchema` (6 tables incl. app_schema/runs/attempts/events/operation_aliases/reconciliation_log, immutability trigger on events, 8 indexes; sqlite.go:229-342), INSERT OR REPLACE app_schema version=1, `PRAGMA user_version = 1`, commit. Then verifySchemaRecord, integrityCheck, `pruneMigrationBackups` (268-291: regular files prefixed `run-control.db.bak.` sorted lexicographically, oldest removed while count > 3; prune errors abort open).

### 2.3 RestoreBackup (migration.go:296-352)
Offline package function (no CLI dispatch reaches it; only migration_test.go:137 calls it). Validates workspace root; backup name must equal its base and carry prefix `run-control.db.bak.`; Lstat requires regular non-symlink ≤512 MiB; `validateBackupIntegrity` opens a `mode=ro&_query_only=1` DSN and runs integrityCheck (physical integrity only — schema version of the backup is not checked here). Then CreateTemp inside `.ultraplan/`, chmod 0600, bounded copy, fsync, close, `os.Rename` over `run-control.db`, `enforcePrivateMode`. Doc comment: callers must stop all UltraPlan processes and restore the matching binary first.

### 2.4 Reconcile (lifecycle.go:301-416)
Grace defaults to `ReconciliationGrace` = 45 s (negative invalid); limit defaults `DefaultReconcileBatch` = 64, max `MaximumReconcileBatch` = 256. Two phases per pass:
- Phase A — unclaimed: runs with terminal NULL, current_attempt NULL, accepted_at older than grace (oldest-first, batch-capped). Per run, `reconcileUnclaimed` (427-479) opens an immediate transaction, rechecks state (terminal/now-claimed → skip), inserts a `terminal` event without attempt_id, CAS-updates `runs … WHERE current_attempt_id IS NULL AND terminal_outcome IS NULL` to lifecycle `interrupted`, liveness `terminal`, proposed_by `reconciler`, reason `owner_never_claimed_after_grace`; lost race returns silently. Evidence class `acceptance_timestamp_only`.
- Phase B — expired leases: JOIN attempts ON current_attempt_id where lease_expires_at older than grace, ordered by lease expiry, capped at remaining budget. For each candidate, probe the recorded PID natively; `reconcileProcessDecision` (481-495): process missing → `interrupted` ("owner_process_missing_after_grace"); probe error (incl. ErrProcessIdentityUnavailable) → `cleanup_uncertain` ("identity_uncertain"); any empty identity field either side → `cleanup_uncertain` ("incomplete"); host/boot/pid/birth mismatch → `interrupted` ("birth_mismatch"); exact live match → no outcome → `markStalled` (CAS `liveness='stalled' WHERE current_attempt_id AND terminal NULL`; lost = ErrStaleFence → skip). Terminal decisions go through `ProposeTerminal` using the attempt's stored fence (owner_id + fencing_generation), so fencing arbitrates against an owner that returned; ErrTerminal/ErrStaleFence are skipped, other errors abort the pass. Both actions record `reconciliation_log` rows (evidence class `safe_identity_only`) via `recordReconciliation` (511-527; its error is discarded with `_ =`) and append to `report.Decisions` regardless of whether a terminal proposal won. `finishReconciliationLog` emits one summary log line and bumps the metric.
- Callers: startup reconcile at repository creation (app/run_control.go:66); owner control loop every `ReconciliationInterval`=10 s (app/run_control.go:289-298); durableOperationManager loop every 10 s (app/durable_operations.go:256). All use `NativeProcessProbe{}` and default options.

### 2.5 Retention (retention.go)
`normalizeRetentionPolicy` (13-33): zero fields fall back to defaults (168h / 720h / 512 MiB); validation: full ≥ 1h, tombstone ≥ 24h and ≥ full, hard quota ≥ 64 MiB and > `ReservedHeadroomBytes` (16 MiB); violation = invalidField.

`Compact(ctx, limit)` (97-160): limit 0→64, bounds 1..256 else invalidField. Pressure = `storageBytes()` ≥ hard-quota×80/100; cutoff = pressure ? now : now − FullHistory/2. Stage 1 candidates: terminal, record_state='full', finished_at ≤ cutoff → `compactTerminalRun(RecordCompacted)`: delete events of types progress/message/omission; CAS-update record_state, history_complete=0, `oldest_retained_sequence = MIN(sequence) | last_sequence+1` WHERE terminal IS NOT NULL (changed ≠ 1 → CodeConflict retryable). Stage 2 candidates: terminal, state full|compacted, finished_at ≤ now − FullHistory → tombstone variant additionally deletes accepted/claimed/lifecycle/recovery event types (warning/finding/artifact/cancellation/terminal survive until expiry); `report.TombstonedRuns++` unconditionally. Stage 3: single DELETE of tombstone runs terminal with finished_at ≤ now − FullHistory − TombstoneHistory, ORDER BY finished_at LIMIT batch. Then best-effort `PRAGMA wal_checkpoint(PASSIVE)` + `PRAGMA incremental_vacuum(64)` (errors ignored), one summary log line, metrics.compactions++.
- Production reachability: the grep-complete caller set of `Compact` in non-test code is `Accept`'s pressure branch alone (sqlite.go:386-389, `Compact(ctx, 64)` when usage ≥ 80% hard quota); neither CLI, web, TUI, nor the periodic loops invoke it.
- Inline per-run compaction `compactRunJournal` (58-95) runs inside every committed `Append` transaction (sqlite.go:687): up to 32 iterations measuring COUNT/SUM of encoded sizes against `MaxRetainedEventsPerRun` 4096 / `MaxRetainedBytesPerRun` 16 MiB; deletes ≤256 oldest progress/message/omission events per pass excluding the just-written sequence; advances the replay boundary each pass; over-cap with nothing removable → CodeQuota "required durable event history reached its bounded capacity"; still over after 32 passes → CodeQuota.

### 2.6 Quota gates
- Accept pre-flight (sqlite.go:384-395): measure storageBytes; ≥80% hard quota → Compact(64) then re-measure; ≥ softQuota (hard − 16 MiB) → CodeQuota retryable "soft quota prevents new acceptance".
- Append (sqlite.go:618-622): usage ≥ hard quota and draft type not reserved (reserved = lifecycle/warning/cancellation/recovery/terminal/omission, sqlite.go:713-720) → CodeQuota retryable "hard quota permits only reserved lifecycle recovery writes".
- Heartbeat (lifecycle.go:24-28): usage ≥ hard quota → CodeQuota retryable "requires the owner to stop active work".
- `storageBytes` (retention.go:35-56) sums every regular file in `.ultraplan/` whose name begins with `run-control.db` — db, `-wal`, `-shm`, and also `.bak.*` backups and same-prefix fixture files.
- Backstop: driver SQLITE_FULL classifies to CodeQuota retryable (classifyStoreError, sqlite.go:1099-1100); fault_test.go:12 pins that a failed append never reports success.

### 2.7 Support export (`run diagnostics --support-export`, run_commands.go:230-377)

Lease/accepted predicates compare against SQLite's `julianday('now')` under the wall clock but against the injected clock when one is injected (sqlite.go:1132-1144, documented dual authority).

MarshalIndent, reject > 1 MiB (measured before the appended newline), write O_CREATE|O_EXCL|O_WRONLY 0600, fsync, deferred remove-on-failure. When the flag is set the command re-runs workspace discovery and config load (251-258) although runRepository already performed both. `--json` envelope status is `string(health.Status)` rather than the constant "ok" used by sibling subcommands.

### 2.8 Local log and sanitize gates
`OpenLocalFileLogger` (local_log.go:37-67): Lstat-rejects symlink/non-dir `.ultraplan` and symlink/non-regular log; O_CREATE|O_APPEND|O_WRONLY 0600; enforcePrivateMode verify. `Log` (69-97): message bounded 256; field keys ≤64 dropped if sensitive (`sensitiveEventField` fragment list); unsafe or >32 KiB values become "[omitted]"; marshal failure or record >4 KiB drops silently; under mutex, Stat-guarded 1 MiB cap drops later records; single append write. `ReadLocalLogs` (113-155): limit 1..500; symlink/oversize/non-regular log → CodeCorrupt (not silently read); bufio scanner capped 4 KiB/line over a 1 MiB+1 LimitReader; malformed/zero-time/empty-message lines skipped; sliding window keeps the newest N records.
`sanitizeEventDraft` (sanitize.go:26-61) is the final storage gate applied inside Append before validation: ~35-field payload allowlist (10-21); deny fragments secret/token/credential/password/prompt/payload/stdout/stderr/path/command (80-88); `unsafeEventValue` rejects NUL/CR/LF, absolute paths (`filepath.IsAbs` plus Windows drive-letter pattern), and credential markers bearer /sk-/ghp_/github_pat_/-----begin private key (90-104); rejected or >32 KiB values increment omission accounting ("unsafe event detail omitted"); oversize total encoding (>128 KiB) replaces the entire draft with a `warning` event `{code: event_detail_oversize}`. `safeEventValue` strips NUL/CR/LF, trims, and truncates by bytes (may split a multi-byte rune).

## 5. Invariants (as implemented)

- A newer-schema database is rejected before any mutation; a corrupt database fails open with ErrCorrupt and its bytes are preserved byte-for-byte (test-pinned, migration_test.go:154-176).
- An already-current database takes no migration lock and is verified (schema record + integrity_check) on every open.
- Migration lock reclaim requires positive proof: parseable valid ProcessIdentity AND native probe result of exactly-not-found or exactly-different-birth; anything uncertain keeps the lock and reports retryable Busy.
- Backup before first-time schema creation only when pre-existing user objects exist; backups are private (0600), bounded (512 MiB), O_EXCL, fsynced, pruned to newest 3, and prune failure aborts the open.
- Restore is fail-closed: name-shape check, regular-file/symlink/size checks, read-only physical integrity validation, temp+fsync+rename, mode enforcement; existing file is overwritten only by rename at the end.
- Reconciliation never infers success: exact live process ⇒ stall mark only (never terminal success); missing/birth-mismatch ⇒ interrupted; any uncertainty ⇒ cleanup_uncertain; unclaimed acceptance ⇒ interrupted after grace with no invented attempt (TRD.md:2208, 2354-2355; test-pinned lifecycle_test.go:176-311).
- Terminal proposals issued by reconciliation ride the attempt fence, so a returned owner's CAS wins and the reconciler skips.
- Compaction preserves the newest commit, never deletes warning/finding/artifact/cancellation/terminal events at the compact stage, always leaves a snapshot row, and advances oldest_retained_sequence monotonically; tombstone expiry deletes whole runs only after full+tombstone history has elapsed and only terminal ones.
- Retention/quota arithmetic: soft = hard − 16 MiB; accept blocked at soft; append restricted to reserved types at hard; heartbeat refused at hard; SQLITE_FULL backstop typed Quota retryable; failed persistence never yields success (fault_test.go).
- Journal content admitted at storage passes the allowlist/deny-fragment/unsafe-value gate with omission accounting; oversize collapses to a warning stub.
- Private-file discipline throughout: 0700 dir, 0600 db/log/backup/export, chmod-then-verify, symlink rejection at dir/db/log/backup surfaces.
- Bounded resources: migration lock content ≤ identity JSON; backups ≤512 MiB ×3; local log 1 MiB/4 KiB-line; export 1 MiB, ≤50 runs ×50 headers, ≤100 evidence rows, ≤100 log records; reconcile batch ≤256; compaction batch ≤256, ≤32 inner passes.

## 6. Trust boundaries

- **Corrupt/hostile pre-existing DB must not be silently replaced**: the named boundary. Controls: unsupported-version rejection before lock; integrity_check gating every open; corrupt-file preservation test; backup-before-migrate for foreign-but-valid schemas; restore validating integrity read-only before rename. The migration path does copy-and-keep (never deletes the original); the only destructive operation is RestoreBackup, which is operator-invoked offline and refuses non-conforming names/files.
- **Lock file contents parsed as identity proof**: `.migrate.lock` bytes are attacker-writable local state parsed as JSON into ProcessIdentity. Design posture: malformed content cannot authorize deletion (fails closed to Busy); valid-looking content authorizes deletion only when the native OS probe disproves liveness (process gone or birth-token mismatch). A local writer can forge an identity for a dead PID to get the lock removed — within a trust model where any local process could equally have deleted the file directly (POSIX-local trust, no auth anywhere).
- Probe inputs (/proc, sysctl) cross from kernel/host into reconciliation decisions; incomplete or unreadable identity maps conservatively to cleanup_uncertain rather than interrupted.
- Sanitizer boundary: producer-supplied payloads/stage/task/detail strings cross into durable storage only via the allowlist + deny-fragment + unsafe-value gate; the local log applies a second, smaller gate to its own structured fields.
- Export boundary: operator-chosen path receives reduced facts only (classification strings, event headers, sanitized log lines); payloads/prompts excluded by construction; absolute workspace-path exclusion is test-enforced rather than code-enforced.
- Config/env retention values cross into policy that gates acceptance; config layer validates bounds first, normalizeRetentionPolicy re-validates.

## 7. External effects & cancellation/retry/restart semantics

External effects per relevant invocation: possible DB/dir/WAL/SHM creation and chmod; lock create/remove; backup create/prune; schema DDL; reconcile mutations (including from nominally read-only commands, because startup Reconcile sits inside pool creation — see sibling pack §2.1/§unknown 2); compaction deletes; log appends; export file creation; checkpoint/vacuum pragmas.
Retry: CodeBusy and CodeUnavailable are flagged retryable; the app write spine loops (appendRunEventWithRetry 5 s deadline; proposeRunTerminalWithRetry 250 ms windows, app/run_control.go:345-368). Migration lock contention returns retryable Busy with no built-in wait loop — the next command retries implicitly. Soft-quota accept refusal is retryable; hard-quota heartbeat refusal is retryable (owner should stop). Stale-lock reclaim retries acquisition exactly once per open.
Cancellation/context: ctx flows into SQL calls; classifyStoreError passes context.Canceled/DeadlineExceeded through unwrapped (sqlite.go:1103-1105). `probeNativeProcess` calls inside lock acquisition and stale detection use `context.Background()`, so they ignore caller cancellation. Reconcile's per-candidate probe honors ctx (process_linux.go:20-22).
Restart/recovery: every fresh process re-runs migrateSchema verification + startup Reconcile on first repository use; reconciliation is idempotent (CAS guards; repeated reconcile after owner exit is test-pinned, process_integration_test.go:177); clock-jump safety pinned by injected-clock test (lifecycle_test.go:233-259). Crash mid-migration leaves either the lock (reclaimable via probe) or a partial schema (user_version 0 + objects → next open backs up and recreates idempotently via CREATE IF NOT EXISTS). Crash between backup and commit leaves a stray backup counted toward storageBytes and pruning.

## 11. Explicit unknowns / open questions (for later reviewers)

1. Retention aging production reachability: `Compact` is invoked only from Accept's ≥80%-pressure branch; tombstoning and expiry therefore occur solely as a side effect of new-acceptance pressure. Whether terminal records age out on any other trigger (timer, command, web action) appears nowhere in-tree.
2. `storageBytes` counts `.bak.*` backups and any `run-control.db*`-prefixed file toward quota gates and Health.StorageBytes; recovery.md:230-231 instructs operators to "free space outside the active database" — the interplay (backups consuming the headroom reserved for recovery writes) is unannotated.
3. Backup pruning sorts lexicographically; the stamp format makes that order-equal to time order only while UTC stamps are unique and monotonic; two migrations within the same nanosecond stamp collide on O_EXCL and abort the migration. Clock steps reorder which backups count as "oldest".
4. `createMigrationBackup` copies only the main DB after `wal_checkpoint(TRUNCATE)`; the checkpoint serializes against active WAL readers only via busy-detection, while the migration lock does not exclude ordinary openers (by stated design, migration.go:33-35). Whether a concurrent opener can invalidate the backup/checkpoint window is unstated.
5. RestoreBackup renames over `run-control.db` without touching pre-existing `-wal`/`-shm` sidecars and without verifying the backup's schema version (physical integrity only); behavior when stale WAL frames meet a restored image is defined only implicitly by SQLite semantics and the runbook's "stop every process / matching binary" precondition.
6. `recordReconciliation` errors are discarded (`_ =` at lifecycle.go:411,352): a decision can complete without its evidence row; report.Decisions are appended even when a terminal proposal did not win. How consumers should treat evidence/report divergence is unstated.
7. Reconcile budget: phase-A results consume the shared batch limit; with more than `limit` unclaimed runs, expired-lease scanning is deferred to later passes (10 s cadence). Drain-order guarantees across phases are otherwise unspecified.
8. Lock acquisition/probe use `context.Background()` internally (migration.go:111,150); caller cancellation cannot interrupt lock waiting or probing — interaction with shutdown sequences is undocumented.
9. `integrityCheck` runs `PRAGMA integrity_check` on every open of every current-version database (all five run doors, web, TUI); cost characteristics for large journals are unbudgeted and unbenchmarked (benchmark_test.go covers append/replay only).
10. `hasApplicationSchema` triggers backup on *any* user object (one stray table in a corrupt-but-parseable file qualifies) while a fully empty DB migrates unbacked; the intended notion of "pre-migration schema" is not further specified.
11. Dual time authority in grace predicates (SQLite `julianday('now')` vs injected clock, sqlite.go:1139-1144) is documented, but the export/backlog age arithmetic mixes Go-side subtraction (Health OldestBacklogAge) with SQL-side comparisons; consistency assumptions across the two clocks are implicit.
12. Support-export truncation is silent (top-50 runs, first-50 event headers, ≤100 logs/evidence) with no presence marker for elided data; `run diagnostics` also repeats discovery/config load inside the support branch after runRepository performed both (run_commands.go:251-258 vs 242-245).
13. Envelope-status divergence for `run diagnostics --json` (health.Status instead of "ok") and absence of run envelopes from the compatibility-sensitive stable-JSON list (cli-reference.md:474-491) leave consumer expectations unpinned.
14. `safeEventValue` truncates by bytes and may split UTF-8 sequences (encoding/json then substitutes U+FFFD at persist time); whether lossy-rune truncation counts as "unsafe detail omitted" accounting is unspecified.
15. Platform asymmetry: on non-linux/darwin the probe always returns ErrProcessIdentityUnavailable, making every expired-lease reconcile land on cleanup_uncertain and migration locks unreclaimable-by-proof; behavior on those platforms rests entirely on the conservative stub (process_other.go).
