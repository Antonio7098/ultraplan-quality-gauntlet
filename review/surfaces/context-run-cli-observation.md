Target: ultraplan-go @ 8eef70f4903b25580719960009a170945bdad9ad (frozen).
Planning context: ultraplan-workspace @ ab12dc38059c9bf485f9aced9075bcd7d924cac5.
Domain: operator-interfaces. Risk: normal. Descriptive only — no defect judgments.

## 1. Purpose

The `ultraplan run` subcommands are the operator's window onto the durable run-control store (`.ultraplan/run-control.db`, owned by `internal/runcontrol`). Five doors: `list` (newest-first filtered page with opaque keyset cursor), `show` (one validated snapshot), `follow` (replay committed events from a decimal sequence, then poll until the run reaches terminal state), `cancel` (reason-whitelisted durable cancellation request), and `diagnostics` (repository health projection plus an optional bounded, payload-free support export). All five are local-only: they never contact a provider (docs/cli-reference.md:492-504). The same repository capability is re-exported as `RunUseCases` for the web and TUI surfaces, making this package the shared read/cancel vocabulary for durable runs. Observation never mutates a run's lifecycle; interruption of `follow` stops observation only (run_commands.go:188-193; user-guide.md:388-391).

## 2. Entrypoints and control flow

### 2.1 Dispatch and repository acquisition
`app.Run` (app.go:88-178) dispatches `run` at app.go:161-162 to `runRun(deps, args[1:])`. `runRun` (run_commands.go:19-40) admits `--help/-h` (prints help without opening any store — test-enforced) and routes to the five handlers; unknown subcommand → ExitUsage. Every handler first calls `runRepository` (run_commands.go:42-59): workspace discovery (`--workspace` flag validated against the `ultraplan.yml` marker, else `ULTRAPLAN_WORKSPACE`, else cwd upward walk; discovery.go:21-61) → ExitWorkspace class on failure; `deps.runControl == nil` → ExitRuntime "run-control.init"; `loadEffectiveConfig` → ExitConfig class; then `deps.runControl.repository(ctx, root.Path, runControlRetentionPolicy(effective.Config))` → ExitRuntime "run-control.open" on failure.

`runControlState.repository` (run_control.go:37-75) is a mutex-guarded per-workspace process singleton: one `*runcontrol.SQLiteRepository` plus one `LocalFileLogger`, retained for process lifetime and closed by `defer runControl.Close()` in `app.Run` (app.go:108-109). Opening performs, in order: `OpenSQLite` (creates `.ultraplan/` 0700 + `run-control.db` 0600 if absent, verifies WAL/FULL/FK/busy pragmas, migrates schema, enforces private modes; sqlite.go:60-134,154-227), logger open + `SetLogger`, then **startup `Reconcile(NativeProcessProbe{}, ReconcileOptions{})`** — so every command, including pure reads, may write (mark owners stalled, terminalize abandoned/expired-lease runs, append reconciliation_log rows). Startup reconcile failure closes both handles and aborts the command ("startup run reconciliation failed", run_control.go:66-70). A second call with a different retention policy errors deterministically ("retention policy changed during the process lifetime", run_control.go:47-49).

`runControlRetentionPolicy` (run_control.go:153-157) converts config strings with `time.ParseDuration`, ignoring parse errors (zero durations later fall back to defaults in `normalizeRetentionPolicy`, retention.go:13-33); quota bytes pass through.

### 2.2 `run list` (run_commands.go:61-103)
Flags: `--json`, `--project`, `--sprint`, `--study`, `--lifecycle` (comma-separated), `--limit` (default 50; help advertises 1..200), `--after <opaque cursor>`. Help is checked before parsing; parse errors or leftover positional args → ExitUsage via `firstFlagError`. `parseLifecycleFilter` (379-392) trims/splits and validates each token against `Lifecycle.IsValid()` (11 valid states, model.go:18-41); unknown token → ExitUsage.

`Repository.List` (lifecycle.go:196-266): limit 0→50, bounds 1..200 else `invalidField`; filters are equality predicates on `project_id`/`sprint_id`/`study_id` plus `lifecycle IN (...)`; ordering is `updated_at DESC, run_id DESC`; `After` decodes an opaque cursor (base64url JSON `{updated_at RFC3339Nano, run_id}`, ≤1024 decoded bytes, timestamp+RunID validated; lifecycle.go:268-291) into a strict keyset predicate `(updated_at < ? OR (updated_at = ? AND run_id < ?))`; fetches limit+1 rows and, when more exist, sets `NextCursor` from the last *included* row before trimming. Each listed run is then loaded through `Snapshot` (N reads), each individually passed through `Snapshot.Validate()` (model.go:333-366). Text output prints `%s  %-20s %-18s %s` (RunID, lifecycle, liveness, slash-joined target via `formatRunTarget` 427-435), "No durable runs found." when empty, and `Next cursor: …` when paginated. JSON output uses the shared envelope (`writeJSON`, json_output.go:20-31: schema_version 1, command, workspace path, status "ok", generated_at, result = Page).

### 2.3 `run show <run-id>` (105-129)
One positional run ID (flags reordered ahead of positionals by `orderRunArgs`, 463-481); `Snapshot(ctx, RunID(arg))` validates the opaque-ID shape first (`run_` + 26 lowercase base32 chars, id.go:65-89) → invalid shape becomes ErrInvalidArgument; missing row becomes ErrNotFound ("run is not retained"). Text rendering `renderRunSnapshot` (416-425): Run / Target / Lifecycle / Liveness / Product status (falls back to literal "unknown") / Cancellation state / Accepted / Updated (RFC3339) / Last sequence / Oldest retained sequence / History complete / Record state, plus `Terminal: outcome (reason)` when present. `--json` wraps the raw snapshot in the envelope with status "ok".

### 2.4 `run follow <run-id>` (131-195)
Flags: `--json` (newline-delimited events), `--after <decimal sequence>` default "0" (ParseUint base 10, 64-bit; non-decimal → ExitUsage). A pre-loop `Snapshot` call validates existence before streaming. Loop body: `Events(ctx, runID, after, 512)` (sqlite.go:809-854 — strictly increasing sequences `> after`, batch cap 512, payloads decoded from stored JSON); text mode prints `seq  type(padded) stage omitted=N` (payload fields are not printed); JSON mode encodes the full persisted Event struct including its sanitized Payload map. Then a fresh `Snapshot`: loop returns nil only when `Lifecycle.IsTerminal() && after >= snapshot.LastSequence`. Otherwise it waits — 250 ms after a full 512-batch or while `after < LastSequence` (catch-up), else 1 s idle — and exits cleanly on `deps.ctx.Done()` with the comment "Observation cancellation never changes the durable run". The timer starts pre-stopped (`NewTimer(0)` + drain). Polling only: the repository Notifier hook is nil in this composition.

### 2.5 `run cancel <run-id>` (197-228)
Flags: `--json`, `--reason` default "user_requested". `canonicalCancellationReason` (394-401) whitelists exactly: `user_requested`, `operator_requested`, `shutdown_requested`, `quota_exceeded`; anything else → ExitUsage. `RequestCancellation` (lifecycle.go:70-134) trims/bounds-checks the reason, opens an immediate transaction, reloads the snapshot, and: if terminal OR cancellation state ≠ none → commits the read and returns `(current, changed=false, nil)` (idempotent no-op); otherwise appends a `cancellation` event (payload `{state: requested, reason}`) and CAS-updates `runs SET lifecycle='cancelling', cancellation_state='requested' … WHERE terminal_outcome IS NULL AND cancellation_state='none' AND last_sequence = ?`; lost race → typed CodeConflict (retryable flag set). CLI text output: `Run: %s / Cancellation: %s / Changed: %t`; JSON output embeds `{changed, run: snapshot}`. Note the request is recorded regardless of owner liveness — delivery to the running owner happens owner-side (control loops acknowledge within their tick; outer-inner-double-fencing seam).

### 2.6 `run diagnostics` (230-276)
Flags: `--json`, `--support-export <path>`. `Repository.Health` (sqlite.go:856-914) reads journal_mode/synchronous/foreign_keys pragmas, counts active runs (accepted/queued/running/cancelling), stalled runs (non-terminal + liveness stalled), cancellation-uncertain rows, reconciliation backlog (unclaimed past grace or expired lease past `ReconciliationGrace`=45 s, joined to attempts), oldest backlog age (min of accepted_at vs lease_expires_at over the backlog), storage bytes (all regular files prefixed `run-control.db` — db/WAL/SHM), soft/hard quotas (soft = hard − 16 MiB reserved headroom), and process-local `LocalMetrics` counters (metrics.go:17-25). Status escalates ok → degraded (≥ soft quota) → failed (≥ hard quota) with appended diagnostic strings. Text output prints nine labeled lines plus `Support export:` when written. `--json` wraps `{health, support_export?}` with the envelope **status field set to `string(health.Status)`** (ok/degraded/failed) rather than the constant "ok" used by the other four subcommands.

Support export (`writeRunSupportExport`, 306-377): unfiltered `List(limit 50)`; config trio (full_history, tombstone_history, workspace_quota_bytes) with source classes from `effective.Sources`; `ReconciliationEvidence(ctx, 100)` behind an anonymous-interface assertion (newest-first, evidence reduced to allowlisted classification strings, lifecycle.go:532-572); `ReadLocalLogs(root, 100)` (local_log.go:113-155 — rejects symlink/oversize/non-regular log files, skips malformed lines, keeps newest N via sliding window); per run, the first 50 events from sequence 0 reduced to `{sequence, type, omission}` — **event payloads are excluded**. The whole document is marshaled indented, rejected if > 1 MiB, then written `O_CREATE|O_EXCL|O_WRONLY` mode 0600 (existing file → error), fsynced, closed, with deferred remove-on-failure. When `--support-export` is set, diagnostics re-runs workspace discovery and config load (251-258) even though `runRepository` already performed both.

### 2.7 `RunUseCases` adapter (run_usecases.go)
Type aliases for all runcontrol DTOs plus sentinel error aliases (invalid-argument/not-found/conflict/unsupported-schema). `RunUseCases` (Runs/Run/RunEvents/CancelRun/RunHealth) is documented as "the surface-neutral durable observation and command boundary. Its DTOs contain only sanitized facts owned by run control"; `repositoryRunUseCases` delegates 1:1 to the Repository. Consumers: web composition (serve_commands.go:80), TUI (`useCases.runs`, tui_commands.go:51), dashboard runs page (sprint_commands.go:407). This adapter is the seam face consumed by web-operation-hub-sse and tui-console.

### 2.8 Write-path context inside the assigned files (run_control.go)
`run_control.go` also hosts the durable write spine used by runtime-backed commands: `controlledRuntime.StartRun` (159-343) Accept→Claim→fence, persists sanitized event drafts through `OnEvent` with content-aware progress coalescing (250 ms window keyed type/stage/task/payload-hash, omission accounting merged into the next commit), a 1 s control goroutine (snapshot poll; requested cancellation ⇒ AcknowledgeCancellation + cancel; Heartbeat every 5 s under a 15 s lease; Reconcile every 10 s), persistence-failure handling that proposes `persistence_degraded` under a 30 s background context, and `terminalOutcome` mapping (deadline→timed_out, cancel→cancelled, err/failed-status→failed, else succeeded). Its sanitization pipeline feeds the journal this surface observes: `runtimeEventDraft` (417-545) maps runtime kinds to event types, drops sensitive keys (`isSensitivePayloadKey` markers secret/token/password/authorization/cookie/api_key/apikey/credential/auth), bounds keys (≤128, no control chars) and values (`boundedPayloadValue`, 32 KiB), flattens one level of nesting with a promote-list (tool/title/detail/text/delta/content/message/action/state/status/native_type/line, ≤30 entries), captures tool identity/arguments/result/error with depth-5 alias search and `redactObservableValue` string-marker redaction ([REDACTED] for bearer /sk-/ghp_/github_pat_/private-key), and records omissions for raw-present/raw-omitted/truncated shapes. A second gate applies at storage: `sanitizeEventDraft` (sanitize.go:26-61) enforces the ~35-field allowlist (sanitize.go:10-21), adds sensitive fragments prompt/payload/stdout/stderr/path/command (80-88), rejects absolute paths/Windows-drive strings/credential markers/control chars (90-104), replaces oversize allowed detail with a warning event, and caps encoded size at 128 KiB. The write spine itself belongs primarily to durable-operation-spine/run-journal-fencing; it is described here because the file sits inside this surface's assigned paths and produces the data these commands display.

## 4. Authoritative state

The authoritative durable state is entirely in `internal/runcontrol`'s SQLite store: `runs` (snapshot columns incl. lifecycle/liveness/record_state/last_sequence/oldest_retained_sequence/history_complete/omission_total/cancellation_*/terminal_*), `attempts` (fencing generations, leases, heartbeats, process birth identity), `events` (immutable — BEFORE UPDATE trigger raises; PK (run_id, sequence)), `operation_aliases`, `reconciliation_log` (evidence bounded to 16 KiB JSON, classification-only exposure on read) (schema sqlite.go:229-342). Durability posture: WAL, synchronous=FULL, foreign_keys=on, busy_timeout 5 s, immediate transactions, pragma verification at open (207-227). This surface owns no new durable state — it projects and (via cancel/reconcile) mutates through the repository. Process-local state: the `runControlState` pool (repo+logger+policy per workspace) and per-process metrics counters (not aggregate across processes). Retention/compaction (full 168h default → compacted → tombstone 720h → delete; per-run caps 4096 events / 16 MiB advancing `oldest_retained_sequence`, retention.go:58-160) reshape what observation can replay; snapshots remain truthful with explicit replay boundaries. The support export is a derived artifact, never authoritative.

## 5. Invariants (as implemented)

- Every command, read or write, opens the same per-process repository handle and runs startup Reconcile before serving; retention policy must be stable per process (run_control.go:37-75).
- Every returned snapshot is validated on read (`Snapshot.Validate` enforces lifecycle/terminal/liveness coherence, timestamps monotonic from acceptance, replay-boundary arithmetic model.go:349-364); corrupt rows fail the whole command rather than render partially.
- List order is deterministic (updated_at DESC, run_id DESC) and pagination is keyset-based; cursors are opaque, bounded (≤1024 decoded bytes), and fully validated (timestamp + canonical RunID).
- Follow delivers strictly increasing sequences > `--after` in batches ≤512, terminates only on terminal-lifecycle-and-drained, and treats SIGINT/SIGTERM as end-of-observation only.
- Cancel requests are idempotent at the store (second request returns changed=false), CAS-arbitrated against concurrent state change, and can never overwrite a won terminal.
- Journal content displayed was gated twice before persistence (app-layer redaction/bounding §2.8 + storage allowlist sanitize.go); text modes print no payload fields at all; support export excludes payloads and asserts exclusion of absolute workspace paths in tests.
- Bounded resources everywhere: list pages ≤200; event batches ≤512; export ≤1 MiB, ≤50 runs × 50 event headers, ≤100 evidence rows, ≤100 log records; local log ≤1 MiB total, ≤4 KiB/line, drop-on-overflow; payload values ≤32 KiB; encoded events ≤128 KiB; per-run journals compacted at 4096 events/16 MiB.
- Private-file discipline: `.ultraplan` 0700, db/log/export 0600, symlink rejection for dir/db/log, chmod verify after set (sqlite.go:154-205; local_log.go:43-65; export O_EXCL).
- Help paths never touch the repository or create files (test-enforced, run_commands_test.go:83-92).
- Stable exit-class mapping for every repository error family (mapRunControlError).

## 6. Trust boundaries

- Operator-supplied run IDs must match the strict opaque base32 grammar before any SQL executes (id.go:73-89); cursors are decoded, size-capped, and semantically validated before use; all SQL is parameterized.
- Trust boundary named in the assignment: **journal payload projection passes sanitizer/redaction before display**. Runtime payloads never reach stdout verbatim: they pass the app-layer redactor/bounder (isSensitivePayloadKey, redactObservableValue, boundedPayloadValue) and then the storage allowlist gate (sanitizeEventDraft); what `follow --json` emits is the persisted, already-sanitized payload map; text modes emit only sequence/type/stage/omission-count; the support export strips payloads entirely.
- Sensitive-content controls operate by deny-marker matching at two layers (secret/token/password/auth*/cookie/api_key/credential…; plus prompt/payload/stdout/stderr/path/command and absolute-path/Windows-drive rejection at storage) rather than positive encoding; `[REDACTED]` substitution applies to tool argument/result trees.
- Local trust model: POSIX permissions are the only access control; any local process/user that can reach `.ultraplan/` can read the store and request cancellations. No auth, session, or origin machinery exists at this door.
- The support export is written to an operator-chosen path with O_EXCL (refuses overwrite) and 0600; its contents include sanitized log records and classification-only reconciliation evidence.
- Config-sourced retention/quota values cross from yml/env into store-opening policy; source classes (default/workspace/env) are recorded into exports for provenance.

## 7. External effects & lifecycle semantics

External effects per invocation: possible creation/chmod of `.ultraplan/{run-control.db,-wal,-shm,run-control.log}`; startup Reconcile writes (stalled marks, interrupted/cleanup_uncertain terminals for expired/unclaimed owners past 45 s grace, reconciliation_log inserts); log appends; `cancel` appends a cancellation event and flips lifecycle to cancelling under CAS; `diagnostics --support-export` creates one new file (never overwrites); stdout/stderr/exit-code emission. Retry semantics: the observation surface itself does not retry — typed retryable flags exist on store errors (Busy/Unavailable) but only write-spine callers loop (appendRunEventWithRetry 5 s deadline, proposeRunTerminalWithRetry 250 ms windows, run_control.go:345-368). Cancellation lanes: this door only records the request; acknowledgement/delivery lives in owner control loops; a request can lose the immutable terminal race to an earlier completion (user-guide.md:384-386 documents this to operators). Restart/recovery: each fresh process re-reconciles on first command; reconcile decisions use exact process-birth identity probing and never infer success from artifact presence or PID existence alone (lifecycle.go:481-495). Error semantics: store failures classify to exit codes without leaking driver messages beyond wrapped cause text; context cancellation during store calls passes through classifyStoreError unwrapped and lands in ExitRuntime via the default arm of mapRunControlError; `follow` swallows ctx.Done as success by design.

## 11. Explicit unknowns / open questions (for later reviewers)

1. Follow exposes no replay-gap signal: events below `oldest_retained_sequence` are simply absent from the stream, while TRD.md:1255 requires typed retention-gap results "rather than silently beginning a partial stream" and the web door implements `cursor_ahead`/`replay_gap` (run_handlers.go:968-979). Whether the CLI's silent-empty behavior satisfies the contract for operators is unresolved in-tree; likewise `--after` beyond `LastSequence` on a non-terminal run polls at 1 Hz indefinitely without feedback.
2. Read commands mutate durable state via startup Reconcile (stall marks, interrupted/cleanup_uncertain terminals, evidence rows). The architecture intends reconciliation-at-open, but operator-facing docs describe list/show/follow purely as inspection; the observable consequence (opening a laptop after a crash rewrites other runs' liveness/terminals as a side effect of a "read") is undocumented in-tree.
3. Envelope status divergence: `run diagnostics --json` sets envelope status to health.Status (ok/degraded/failed) while the other four subcommands hard-code "ok"; run JSON surfaces are absent from the compatibility-sensitive stable-JSON list (cli-reference.md:474-491), so consumer expectations are unpinned.
4. `runControlRetentionPolicy` ignores `time.ParseDuration` errors (run_control.go:154-156); config.Load validation should catch malformed yml/env upstream, but the swallow-pattern's interaction with normalizeRetentionPolicy defaults is unannotated.
5. Support export truncation is silent: first 50 events per run, ≤50 runs, ≤100 logs/evidence rows — no marker records that deeper history exists; size check measures marshaled bytes before the appended newline (off-by-one immaterial but unspecified).
6. `runDiagnostics` repeats discoverWorkspace + loadEffectiveConfig inside the support branch although runRepository already performed both (251-258 vs 242-245); intent unstated.
7.
